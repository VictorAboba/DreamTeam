# DreamTeam

Фреймворк на Python для **самоорганизующегося роя ИИ-агентов**. У агентов человеческие имена, они работают
на общей онлайн-доске задач ради одной глобальной цели, переписываются напрямую друг с другом и с вами,
обсуждают задачи в ветках, делят общий git-workspace, ставят себе триггеры и сами пишут себе
инструменты в виде MCP-серверов. Сам рой тоже является MCP-сервером: к нему можно подключить
Claude Code, чтобы наблюдать за роем, управлять им или вступить в него как участник.

Всё начинается со стартовой страницы: на ней список **сессий** (каждая сессия — отдельный рой со своей целью),
кнопка «Начать новую сессию» и **настройки** (эндпоинты и ключи моделей, лимиты, консоль, MCP, трейсы).
Для любого агента можно открыть **трейсы**: каждое пробуждение по шагам, с вызовами LLM, мыслями и
инструментами, токенами, стоимостью и временем.

## Возможности

| | |
|---|---|
| **Доска задач** | Глобальная цель роя и задачи, которые рой ставит себе сам. У каждой задачи есть **цель** (зачем она нужна и что считается успехом), исполнитель, ревьюер, статус (`todo → in_progress → waiting → review → done / failed / cancelled`), приоритет, теги, подзадачи и зависимости. Взятие задачи атомарное, задачу с невыполненными зависимостями взять нельзя. |
| **Обсуждение задачи** | У каждой задачи своя ветка обсуждения: посты, ответы (`reply_to`) и упоминания `@Имя Фамилия`. Автор задачи, исполнитель, ревьюер, все писавшие в ветку и упомянутые получают уведомления. |
| **Самоорганизация** | Лидера нет. При постановке цели на доске появляется задача планирования. Её берёт первый свободный агент, а остальные подключаются к готовым задачам. Если есть свободные задачи, планировщик будит простаивающих агентов. |
| **Имена и найм** | Каждый агент получает уникальное человеческое имя: «Анна Смирнова» или «John Smith». Агенты нанимают новых ролевых агентов (`hire_agent`) в пределах лимита. |
| **Сообщения** | Личные сообщения одному, нескольким или всем участникам, а также пользователю. Если вы написали агенту, его текстовый ответ придёт вам. |
| **Общий workspace** | Общие файлы под git: каждое изменение автоматически коммитится от имени агента. Есть блокировки файлов на время правки. |
| **Консоль** | Агенты выполняют команды (bash или PowerShell) в workspace. Ключи API из окружения скрыты. |
| **Триггеры** | Безопасный мини-язык условий любой сложности: `done(1, 5)`, `status(3) in (failed, cancelled) or count(status=done, tag="api") >= 3`, `message(sender="Анна Смирнова")`, `comment(task=7)`, `file_changed("report.md")`, `after("2026-10-09 18:00")`, `every(1800)`. По срабатыванию агент просыпается, отправляется сообщение, меняется статус или создаётся задача. |
| **MCP-мастерская** | Агент пишет MCP-сервер на Python (`mcp_create`). Сервер проходит автоматическую проверку и регистрируется с областью видимости: личный, для задачи или для всего роя. Им пользуются все допущенные агенты (`mcp_tools`, `mcp_call`). Серверы роя попадают в общую библиотеку и доступны в следующих запусках. По желанию новые MCP требуют одобрения пользователя. |
| **Рой как MCP** | `/mcp` по HTTP или `dreamteam mcp` по stdio. Внешний клиент действует как пользователь или вступает в рой (`join_swarm`) и работает как участник. |
| **Сессии** | Стартовая страница со списком сессий: у каждой видны статус, цель, прогресс задач, команда, расходы, модель и время последней активности. Сессию можно открыть, остановить, запустить снова или удалить. Остановленную сессию тоже можно открыть: доска, переписка, файлы и трейсы доступны для просмотра. Каждая сессия — независимый рой со своей доской, перепиской, workspace, MCP и трейсами. Сессии, которые работали при остановке сервера, возобновляются при следующем запуске. |
| **Настройки в UI** | Профили моделей: Anthropic, OpenAI, OpenRouter, Ollama, vLLM, LM Studio или свой OpenAI-совместимый эндпоинт. Ключ задаётся переменной окружения или самим значением, в браузер он не уходит (как и значения `env` внешних MCP-серверов: они показаны замаскированными). Есть кнопки «Проверить» (список моделей эндпоинта) и «Тестовый запрос». Также настраиваются значения по умолчанию для новых сессий, агенты, консоль, workspace, MCP, трейсы и сервер. Изменения моделей и лимитов сразу применяются к работающим сессиям, настройки сервера — после перезапуска. |
| **Трейсы агентов** | Каждое пробуждение агента сохраняется как трейс из шагов: что его разбудило; каждый вызов LLM с моделью, мыслями, ответом, вызовами инструментов, токенами (включая кэш), стоимостью, задержкой и причиной остановки; ретраи; каждый инструмент с полными аргументами и результатом; сжатие контекста; итог. Для любого вызова LLM можно открыть точный контекст запроса, даже после сжатия истории. Вкладка «Трейсы» показывает водопад шагов и статистику по инструментам и моделям. Трейсы можно выгрузить в JSON/JSONL, читать через `dreamteam traces` и через MCP-инструмент `agent_traces`. Трейсы пишутся и для внешних участников (Claude Code через MCP). |
| **Терминал в стиле Claude Code** | `dreamteam` в терминале открывает интерактивный интерфейс. В нём есть приветствие, поле ввода в рамке и строка статуса. Слэш-команды и `@агенты` подсказываются при наборе. Лента действий роя оформлена так: `⏺ Агент · инструмент(...)` и под ней `⎿ результат`. Задачи отмечаются как `☐ ◐ ☒`. Пока агенты работают, крутится спиннер со временем, токенами и стоимостью, а `esc` ставит рой на паузу. Одобрение MCP-серверов идёт через диалог. `!команда` выполняет команду в workspace. `dreamteam -p "цель"` работает без интерфейса для скриптов и CI и выводит `text`, `json` или `stream-json`. |
| **Онлайн-доска** | Веб-интерфейс с живыми обновлениями: канбан с перетаскиванием, карточки задач с обсуждением, чат с любым агентом и лента его действий (мысли, вызовы инструментов, результаты), а также вкладки с лентой событий роя, файлами, MCP и триггерами. Есть RU/EN и светлая/тёмная тема. |
| **Модели** | Claude API, OpenAI, OpenRouter, vLLM, Ollama и любой OpenAI-совместимый прокси. Профили моделей задаются в конфиге, разным агентам можно назначить разные модели. |
| **Бюджет** | Учёт токенов и денег по каждому агенту. При исчерпании бюджета рой встаёт на паузу. Есть лимит числа агентов. |
| **Языки** | Промпты агентов на русском или английском (`swarm.language`; язык можно задать и для отдельного агента). |
| **Песочница** | `dreamteam sandbox` запускает весь рой в Docker вместе с консолью агентов и их MCP-серверами. |
| **Надёжность** | Всё хранится в одном SQLite-файле. После перезапуска рой продолжает работу с того же места: история агентов восстанавливается, а прерванные вызовы инструментов корректно закрываются. |

## Быстрый старт

```bash
uv sync                       # или: pip install -e .
```

```bash
uv run dreamteam                                   # интерфейс в терминале (в стиле Claude Code)
uv run dreamteam "Сделай игру змейка на Python"    # сразу новая сессия с этой целью
uv run dreamteam serve                             # только веб-интерфейс (без терминала — по умолчанию)
```

В терминале `dreamteam` открывает [терминальный интерфейс](#терминальный-интерфейс). Если сервер ещё не
запущен, он стартует в том же процессе, поэтому веб-доска по адресу `http://127.0.0.1:8765` тоже доступна.
`dreamteam serve` запускает только веб-интерфейс. Откроется стартовая страница `http://127.0.0.1:8765`:

1. На вкладке **«Настройки» → «Модели и эндпоинты»** выберите провайдера и модель, укажите ключ (имя
   переменной окружения, например `ANTHROPIC_API_KEY`, или сам ключ) и нажмите «Проверить».
2. На вкладке **«Сессии»** нажмите **«Начать новую сессию»** и опишите цель. Рой создаст план и начнёт работу,
   а вы попадёте на доску сессии `/s/<id>/`.

Сессии и настройки хранятся в домашней папке DreamTeam: `~/DreamTeam` (её задают `--home` или переменная
`DREAMTEAM_HOME`). Там лежат `dreamteam.toml` с глобальными настройками и `sessions/<id>/` с данными, файлами
workspace и трейсами каждой сессии. Сессию можно сразу создать из командной строки:
`dreamteam serve --goal "Сделать CLI-утилиту для конвертации CSV в JSON с тестами" --title "CSV → JSON"`.

Команды:

| команда | что делает |
|---|---|
| `dreamteam ["цель"]` / `dreamteam tui` | терминальный интерфейс; `-c` — продолжить последнюю сессию, `-r [ID]` — выбрать или открыть сессию; для новой сессии: `--model`, `--agents`, `--max-agents`, `--budget`, `--title` |
| `dreamteam -p "цель"` | без интерфейса: выполнить цель и вывести итог (`--output-format text/json/stream-json`, `--verbose`, `--timeout`, `-c`/`-r ID` — следующее указание существующей сессии); текст из stdin добавляется к запросу |
| `dreamteam serve [HOME]` | стартовая страница, настройки, доски всех сессий и MCP (`--host`, `--port`, `--goal` и `--title`, `--no-browser`, `--no-console`); без терминала `dreamteam` запускает именно его |
| `dreamteam sessions` / `dreamteam status` | список сессий и запущен ли сервер |
| `dreamteam console [--session ID]` | консольный чат с работающей сессией (`/help` — команды) |
| `dreamteam traces [Агент] [--session ID] [--id N] [--span N --context] [--status failed] [--json]` | трейсы агентов в терминале (с сервером и без него) |
| `dreamteam mcp` | DreamTeam как MCP-сервер по stdio (прокси к запущенному серверу или свой процесс) |
| `dreamteam sandbox [HOME]` | то же в Docker |
| `dreamteam init DIR` + `dreamteam run DIR` | прежний режим: один рой в папке проекта, без стартовой страницы |

Другую домашнюю папку этим командам (кроме `init` и `run`) передают через `--home ПАПКА`.

Ключи API не обязательно хранить в настройках: если указано `api_key_env`, ключ берётся из переменной окружения.
Для Claude подходит и профиль `ant auth login`.

### Подключение к Claude Code

Если DreamTeam запущен, подключитесь по HTTP:

```bash
claude mcp add --transport http dreamteam http://127.0.0.1:8765/mcp
```

Без запущенного сервера Claude Code может сам поднять DreamTeam через stdio. Если сервер уже запущен, команда станет прокси к нему:

```bash
claude mcp add dreamteam -- dreamteam mcp
```

Через `/mcp` доступны инструменты сессий: `sessions_list`, `session_create(title, goal, ...)`, `session_start` и
`session_stop`. Остальные инструменты работают внутри сессии, её задаёт параметр `session="<id>"`; по умолчанию
выбирается работающая сессия. Подключиться к одной сессии напрямую можно по адресу `http://127.0.0.1:8765/s/<id>/mcp`.

По умолчанию Claude Code действует как пользователь роя: задаёт цель, смотрит доску, пишет агентам, одобряет MCP,
читает трейсы (`agent_traces`) и ждёт сообщений через `wait_for_events`. Чтобы работать внутри роя, нужно вызвать
`join_swarm(role=...)` и затем передавать `as_agent="<имя>"`: так можно брать задачи, писать файлы, выполнять
команды и создавать MCP.

### Песочница Docker

```bash
dreamteam sandbox ~/DreamTeam --goal "..."
```

Команда собирает образ `dreamteam:latest` и запускает DreamTeam в контейнере. Домашняя папка монтируется в `/swarm`,
стартовая страница доступна на `127.0.0.1:8765`. Альтернатива: `SWARM_DIR=~/DreamTeam docker compose up --build`.
Локальные модели (Ollama, vLLM) из контейнера доступны по адресу `http://host.docker.internal:<порт>`.

## Трейсы агентов

Откройте вкладку **«Трейсы»** на доске сессии или нажмите «📈 Трейсы» в окне агента.

* Слева список пробуждений агентов с фильтрами по агенту и статусу (`done`, `error`, `step_limit`, `refusal`,
  `interrupted`, «только с ошибками»).
* Справа сводка трейса: шаги, вызовы LLM, инструменты, ошибки, токены (вход/выход/кэш), стоимость и связанные задачи.
  Ниже водопад шагов на шкале времени.
* По клику шаг раскрывается.
  * У вызова LLM видны модель, причина остановки, токены, стоимость, мысли, ответ и вызовы инструментов, а кнопка
    «Контекст запроса» показывает системный промпт, инструменты и все сообщения, которые видела модель.
  * У инструмента видны полные аргументы и результат. Если модель получила урезанный результат, это помечено.
* «📊 Статистика» показывает вызовы, ошибки и среднее время по инструментам и моделям.
* «⬇ Экспорт» выгружает трейс в JSON (с контекстами или без), а все трейсы агента — в JSONL.

То же доступно без UI:

* REST сессии (пути от `/s/<id>`): `/api/traces`, `/api/traces/<n>`, `/api/spans/<n>`, `/api/spans/<n>/context`,
  `/api/traces/stats`, `/api/traces/<n>/export`, `/api/agents/<имя>/traces.jsonl`.
* Терминал: `dreamteam traces "Анна Смирнова" --status failed`.
* MCP: `agent_traces(agent=..., trace_id=..., span_id=..., context=true)`.

Настройки находятся в секции `[tracing]`: `enabled`, `max_payload_chars` (лимит одного поля) и `retention_days`
(через сколько дней удалять старые трейсы; `0` — хранить всегда).

## Конфигурация (`dreamteam.toml`)

Глобальные настройки лежат в `<home>/dreamteam.toml`. Их удобнее менять на вкладке «Настройки»: страница проверяет
значения перед сохранением и хранит предыдущую версию в `dreamteam.toml.bak`. Ручная правка файла тоже работает,
но комментарии при сохранении из UI не сохраняются; правка файла при работающем сервере подхватывается. При создании
сессии можно переопределить язык, число агентов, бюджет, профиль модели, стартовые роли, число шагов и одобрение MCP.
Эти значения хранятся в `sessions/<id>/session.json`; остальное берётся из глобальных настроек. Цель задаётся при
создании сессии (ключ `goal` в `[swarm]` используется только в режиме `dreamteam run` и в сессии `main` бывшего
проекта).

```toml
[swarm]                  # значения по умолчанию для новых сессий
name = "Мой рой"
language = "ru"          # язык промптов агентов: ru | en
start_agents = 3         # сколько агентов стартует
max_agents = 8           # максимум (агенты нанимают новых сами)
max_cost_usd = 5.0       # бюджет; при исчерпании — пауза
starting_roles = []      # ["Аналитик", "Разработчик", "Тестировщик"]

[agents]
default_model = "default"
max_steps_per_turn = 40
context_tokens = 120000  # порог сжатия истории агента в резюме

[models.default]         # Claude
provider = "anthropic"
model = "claude-opus-5-5"
api_key_env = "ANTHROPIC_API_KEY"
effort = "medium"
fallbacks = "default"           # серверный fallback при отказе модели (beta)
thinking_mismatch = "drop_block" # не падать при изменении префикса диалога (beta)

[models.local]           # Ollama / vLLM / OpenRouter — любой OpenAI-совместимый API
provider = "openai"
base_url = "http://localhost:11434/v1"
model = "qwen3:32b"
api_key = "ollama"
input_price = 0
output_price = 0

[mcp]
require_approval = false
[mcp.external.fetch]     # внешние MCP-серверы для роя
command = ["uvx", "mcp-server-fetch"]
description = "Загрузка веб-страниц"

[tracing]
enabled = true           # трейсы агентов
max_payload_chars = 200000
retention_days = 0       # 0 — хранить всегда

[server]
host = "127.0.0.1"
port = 8765
resume_sessions = true   # возобновлять сессии, которые работали при остановке
```

Для цен известных моделей Claude используются встроенные значения. Для остальных моделей укажите
`input_price` и `output_price` в долларах за 1M токенов. Если провайдер сам сообщает стоимость (как OpenRouter), берётся она.

## Терминальный интерфейс

`dreamteam` в терминале выглядит и управляется как Claude Code:

- **Первое сообщение без сессии** становится целью новой сессии: рой собирает команду и начинает работу.
  Дальше сообщения уходят текущему адресату. Он показан в заголовке рамки: это агент, который написал вам
  последним, иначе ответственный за планирование, иначе все. `@Имя текст` пишет конкретному агенту и делает
  его адресатом, `@all` пишет всем.
- **Лента.** Вызовы инструментов агентов выглядят как `⏺ Анна Смирнова · task_claim(task_id=3)` с результатом
  `⎿` под ними. Сообщения вам выводятся целиком в markdown, задачи — списком дел `☐ ◐ ◑ ☒`, цель — рамкой.
  `Shift+Tab` переключает подробность: тихо, обычно (по умолчанию) или подробно с мыслями агентов и
  результатами инструментов. `Ctrl+O` включает подробный режим.
- **Спиннер** `✻ Совещаются… (12s · ↑ 4.2k ↓ 310 · $0.12 · esc — пауза)` виден, пока агенты работают.
  `Esc` ставит рой на паузу, `/pause` снимает её.
- **Команды** (`/` открывает подсказки): `/new [цель]`, `/sessions`, `/resume ID`, `/goal`, `/board`,
  `/task N`, `/agents`, `/to Имя`, `/hire Роль | инструкции`, `/trace [Имя | N]`, `/span N [ctx]`,
  `/files [путь]`, `/cat путь`, `/cost`, `/status`, `/model [профиль]`, `/pause`, `/budget N`, `/max N`,
  `/approve имя`, `/reject имя`, `/stop`, `/web`, `/settings`, `/verbose`, `/lang ru|en`, `/clear`, `/exit`.
- **`!команда`** выполняет команду в workspace сессии. Это работает, когда сервер локальный.
- **Клавиши:**
  - `Enter` — отправить;
  - `Alt+Enter`, `Ctrl+J` или `\` в конце строки — новая строка;
  - `↑/↓` — история;
  - `Tab` — дополнить;
  - `Ctrl+L` — очистить экран;
  - `Ctrl+C` дважды или `Ctrl+D` — выход;
  - `?` — справка по клавишам.
- **Одобрение MCP.** Когда агент создаёт MCP-сервер, а в настройках включено одобрение, поле ввода
  сменяется диалогом «разрешить / отклонить».

Если сервер для домашней папки уже запущен (`dreamteam serve`), интерфейс подключается к нему. Иначе сервер
стартует в том же процессе, а при выходе сессии останавливаются; `dreamteam -c` продолжит последнюю.
В Git Bash (mintty) запускайте `winpty dreamteam` или пользуйтесь Windows Terminal / PowerShell.

Неинтерактивный режим для скриптов:

```bash
dreamteam -p "Напиши скрипт, который считает строки кода в репозитории" --output-format json
cat error.log | dreamteam -p "Найди причину ошибки" -c
```

Вопросы агентов к пользователю в этом режиме получают ответ «решите сами» (`--no-auto-reply` это отключает).
Коды выхода:

- `0` — цель достигнута;
- `2` — исчерпан бюджет;
- `3` — истёк `--timeout`;
- `1` — ошибка;
- `130` — Ctrl+C.

## Команды консоли

`@Имя Фамилия текст` — написать агенту, `/chat Имя` — диалоговый режим, `/all текст` — написать всем,
`/goal Заголовок | описание`, `/task Заголовок | цель`, `/board`, `/agents`, `/status`,
`/show N` (задача и её обсуждение), `/comment N текст`, `/hire Роль | инструкции`, `/pause`, `/resume`,
`/budget 10`, `/max 6`, `/approve имя`, `/reject имя`, `/trace [Имя | N]` (трейсы), `/span N [ctx]` (шаг трейса

Консоль подключается к работающей сессии: `dreamteam console` (или `dreamteam console --session 003-snake`).
Это простой построчный клиент для терминалов, где не работает [терминальный интерфейс](#терминальный-интерфейс).

## Инструменты агентов

Набор инструментов минимален: только взаимодействие с роем и консоль. Всё остальное агенты пишут себе
сами в виде MCP-серверов.

* Доска: `board`, `task_get`, `task_create`, `task_claim`, `task_update`, `task_complete`, `task_review`,
  `task_comment`, `task_discussion`.
* Общение: `send_message`, `read_messages`.
* Команда: `agents`, `hire_agent`, `retire_agent`, `update_notes` (блокнот, который переживает сжатие контекста),
  `wait`, `goal_complete`.
* Триггеры: `trigger_create`, `trigger_list`, `trigger_delete`.
* Файлы и консоль: `read_file`, `write_file`, `edit_file`, `list_files`, `lock_file`, `shell`.
* MCP: `mcp_create`, `mcp_list`, `mcp_tools`, `mcp_call`.

Шаблон MCP-сервера, который пишут агенты (mcp 2.x):

```python
from mcp.server.mcpserver import MCPServer

mcp = MCPServer("csv_tools")

@mcp.tool()
def count_rows(path: str) -> int:
    """Count data rows in a CSV file."""
    ...

if __name__ == "__main__":
    mcp.run()
```

## Как это устроено

```
 Стартовая страница ─REST+WS─► Launcher (SessionManager, настройки, /mcp)
                                  │  /s/<id>/…  — доска, REST, WS и MCP одной сессии
 Веб-доска / консоль ──REST+WS──┐ ▼                       ┌── агенты-LLM (ReAct, свой asyncio-таск) ── Tracer
 Claude Code ───────────MCP─────┤   Swarm сессии          ├── внешние участники через MCP (join_swarm) ── Tracer
                                └─► Board · Mailbox · Workspace(git) · Triggers · MCPForge · Budget · Tracer
                                     └── SQLite сессии: задачи, обсуждения, сообщения, уведомления, история агентов,
                                         архив истории, трейсы и спаны, журнал событий
```

* Агент спит, пока для него нет событий. Его будят сообщения, назначения, посты в обсуждениях,
  разблокированные задачи и триггеры. При пробуждении агент получает сводку: что произошло, цель роя,
  свои задачи, свободные задачи и свой блокнот. Дальше идёт цикл ReAct: LLM, инструменты, LLM… пока агент не вызовет `wait`.
* История агента ведётся только на дописывание: thinking-блоки Claude привязаны к точному префиксу диалога, и
  ради этого же работает кэш промптов. Системный промпт фиксируется при найме, набор инструментов
  постоянный, а MCP-инструменты вызываются через `mcp_call`. Когда контекст переполняется, история сжимается в резюме.
* Каждое изменение пишется в журнал событий. Из него строятся живые обновления UI, лента и проверка триггеров.
* Контракт модулей описан в [docs/SPEC.md](docs/SPEC.md).

Идеи взяты у Claude Code Agent Teams (общий список задач, захват задач, почтовые ящики), Gas Town / Beads
(состояние в git, продолжение после сбоя), CAMEL Workforce и Magentic-One (каналы задач, перепланирование),
MetaGPT (подписка на события), Strands Swarm (защита от зацикливания), Letta (блокнот, переживающий сжатие),
Alita (агенты сами создают MCP и складывают их в библиотеку), A2A (жизненный цикл задач с ожиданием ввода)
и blackboard-архитектуры (агенты сами вызываются на задачи).

## Безопасность

* Агенты выполняют команды и код MCP-серверов с правами пользователя, который запустил рой. Для недоверенных
  задач используйте `dreamteam sandbox` (Docker).
* Секреты (`*_API_KEY`, `*_TOKEN`, `*SECRET*`, …) не передаются в консоль агентов и их MCP-серверы,
  если вы явно не разрешили их в `shell.pass_env`.
* Хаб по умолчанию слушает только `127.0.0.1`. Не открывайте его в сеть без обратного прокси с авторизацией.
* Защита от DNS-rebinding и межсайтовых запросов действует при любом адресе привязки (включая `0.0.0.0` в Docker):
  по IP и `localhost` доступ есть всегда, другие имена хостов перечислите в `DREAMTEAM_ALLOWED_HOSTS=board.example.com`.
  `DREAMTEAM_PUBLIC_URL` задаёт адрес доски, который видят пользователи (его выставляет `dreamteam sandbox`).
* `docker compose up --build` отправляет в Docker только исходники (`.dockerignore`): ни `.venv`, ни `.git`, ни папки
  роёв с их базами и `dreamteam.toml` с ключами в образ не попадают.
