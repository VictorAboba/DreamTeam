# DreamTeam

Фреймворк на Python для **самоорганизующегося роя ИИ-агентов**. У агентов человеческие имена, они работают
на общей онлайн-доске задач ради одной глобальной цели, переписываются напрямую друг с другом и с вами,
обсуждают задачи в ветках, делят общий git-workspace, ставят себе триггеры и сами пишут себе
инструменты в виде MCP-серверов. Сам рой тоже является MCP-сервером: к нему можно подключить
Claude Code, чтобы наблюдать за роем, управлять им или вступить в него как участник.

Всё начинается со стартовой страницы: на ней список **сессий** (каждая сессия — отдельный рой со своей целью),
кнопка «Начать новую сессию» и **настройки** (эндпоинты и ключи моделей, лимиты, консоль, MCP, трейсы).
Для любого агента можно открыть **трейсы**: каждое пробуждение по шагам, с вызовами LLM, мыслями и
инструментами, токенами, стоимостью и временем.

## Возможности

| | |
|---|---|
| **Доска задач** | Глобальная цель роя и задачи, которые рой ставит себе сам. У каждой задачи есть **цель** (зачем она нужна и что считается успехом), исполнитель, ревьюер, статус (`todo → in_progress → waiting → review → done / failed / cancelled`), приоритет, теги, подзадачи и зависимости. Взятие задачи атомарное, задачу с невыполненными зависимостями взять нельзя. Задачу агента принимает другой агент (независимое ревью); если больше некому — вы. |
| **Обсуждение задачи** | У каждой задачи своя ветка обсуждения: посты, ответы (`reply_to`) и упоминания `@Имя Фамилия`. Автор задачи, исполнитель, ревьюер, все писавшие в ветку и упомянутые получают уведомления. |
| **Самоорганизация** | Лидера нет. При постановке цели на доске появляется задача планирования. Её берёт первый свободный агент, а остальные подключаются к готовым задачам. Если есть свободные задачи, планировщик будит простаивающих агентов. |
| **Имена и найм** | Каждый агент получает уникальное человеческое имя: «Анна Смирнова» или «John Smith». Агенты нанимают новых ролевых агентов (`hire_agent`) в пределах лимита. Роли берутся из [каталога ролей](#роли-и-стартовая-команда), его можно дополнить своими. |
| **Сообщения** | Личные сообщения одному, нескольким или всем участникам, а также пользователю. Если вы написали агенту, его текстовый ответ придёт вам. |
| **Общий workspace** | Общие файлы под git: каждое изменение автоматически коммитится от имени агента, вручную агенты не коммитят. Временные файлы агенты кладут в `.scratch/` (у каждого своя папка): она не коммитится, и DreamTeam её не очищает. Есть блокировки файлов на время правки. |
| **Консоль** | Агенты выполняют команды (bash или PowerShell) в workspace. Ключи API из окружения скрыты. Команда, которая не уложилась в свой тайм-аут, не обрывается, а продолжает работать как **фоновый процесс**: агент сразу получает её вывод и занимается другим, а об окончании процесса узнаёт с кодом возврата и концом вывода. Dev-сервер, сборку или долгие тесты агент может и сам запустить в фоне. Фоновые процессы видны на вкладке «Процессы» веб-доски и по команде `/jobs` в терминале, там же их можно остановить. Пауза роя их не останавливает, остановка сессии — останавливает. |
| **Триггеры** | Безопасный мини-язык условий любой сложности: `done(1, 5)`, `status(3) in (failed, cancelled) or count(status=done, tag="api") >= 3`, `message(sender="Анна Смирнова")`, `comment(task=7)`, `file_changed("report.md")`, `after("2026-10-09 18:00")`, `every(1800)`. По срабатыванию агент просыпается, отправляется сообщение, меняется статус или создаётся задача. |
| **MCP-мастерская** | Агент пишет MCP-сервер на Python (`mcp_create`). Сервер проходит автоматическую проверку и регистрируется с областью видимости: личный, для задачи или для всего роя. Им пользуются все допущенные агенты (`mcp_tools`, `mcp_call`). Серверы роя попадают в общую библиотеку и доступны в следующих запусках. По желанию новые MCP требуют одобрения пользователя. |
| **Рой как MCP** | `/mcp` по HTTP или `dreamteam mcp` по stdio. Внешний клиент действует как пользователь или вступает в рой (`join_swarm`) и работает как участник. |
| **Сессии** | Стартовая страница со списком сессий: у каждой видны статус, цель, прогресс задач, команда, расходы, модель и время последней активности. Сессию можно открыть, остановить, запустить снова или удалить. Остановленную сессию тоже можно открыть: доска, переписка, файлы и трейсы доступны для просмотра. Каждая сессия — независимый рой со своей доской, перепиской, workspace, MCP и трейсами. Сессии, которые работали при остановке сервера, возобновляются при следующем запуске. Сессию можно [перенести в другую папку или направить на существующий проект](#папка-сессии-и-существующий-проект) командой `/cd`. |
| **Настройки в UI** | Профили моделей: Anthropic, OpenAI, OpenRouter, Ollama, vLLM, LM Studio или свой OpenAI-совместимый эндпоинт. Ключ задаётся переменной окружения или самим значением, в браузер он не уходит (как и значения `env` внешних MCP-серверов: они показаны замаскированными). Есть кнопки «Проверить» (список моделей эндпоинта) и «Тестовый запрос». Также настраиваются значения по умолчанию для новых сессий, агенты, консоль, workspace, MCP, трейсы и сервер. Изменения моделей и лимитов сразу применяются к работающим сессиям, настройки сервера — после перезапуска. |
| **Трейсы агентов** | Каждое пробуждение агента сохраняется как трейс из шагов: что его разбудило; каждый вызов LLM с моделью, мыслями, ответом, вызовами инструментов, токенами (включая кэш), стоимостью, задержкой и причиной остановки; ретраи; каждый инструмент с полными аргументами и результатом; сжатие контекста; итог. Для любого вызова LLM можно открыть точный контекст запроса, даже после сжатия истории. Вкладка «Трейсы» показывает водопад шагов и статистику по инструментам и моделям. Трейсы можно выгрузить в JSON/JSONL, читать через `dreamteam traces` и через MCP-инструмент `agent_traces`. Трейсы пишутся и для внешних участников (Claude Code через MCP). |
| **Терминал в стиле Claude Code** | `dreamteam` в терминале открывает интерактивный интерфейс. В нём есть приветствие, поле ввода в рамке и строка статуса. Слэш-команды и `@агенты` подсказываются при наборе. Лента действий роя оформлена так: `⏺ Агент · инструмент(...)` и под ней `⎿ результат`. Задачи отмечаются как `☐ ◐ ☒`. Пока агенты работают, крутится спиннер со временем, токенами и стоимостью, а `esc` ставит рой на паузу. Одобрение MCP-серверов идёт через диалог. `!команда` выполняет команду в workspace. `dreamteam -p "цель"` работает без интерфейса для скриптов и CI и выводит `text`, `json` или `stream-json`. |
| **Онлайн-доска** | Веб-интерфейс с живыми обновлениями: канбан с перетаскиванием, карточки задач с обсуждением, чат с любым агентом и лента его действий (мысли, вызовы инструментов, результаты), а также вкладки с лентой событий роя, файлами, MCP, триггерами и фоновыми процессами агентов (их вывод и кнопка «Остановить»). Сообщения, описания и итоги задач, обсуждения, цель и `.md`-файлы показаны форматированным Markdown (безопасное подмножество: HTML из текста выводится как текст); код в файлах и в блоках кода подсвечивается (около 30 языков, без внешних библиотек). Есть RU/EN и светлая/тёмная тема. |
| **Модели** | Claude API, OpenAI, OpenRouter, vLLM, Ollama и любой OpenAI-совместимый прокси. Профили моделей задаются в конфиге, разным агентам можно назначить разные модели. |
| **Бюджет** | Учёт токенов и денег по каждому агенту. При исчерпании бюджета рой встаёт на паузу. Есть лимит числа агентов. |
| **Языки** | Промпты агентов на русском или английском (`swarm.language`; язык можно задать и для отдельного агента). |
| **Песочница** | `dreamteam sandbox` запускает весь рой в Docker вместе с консолью агентов и их MCP-серверами. |
| **Надёжность** | Всё хранится в одном SQLite-файле. После перезапуска рой продолжает работу с того же места: история агентов восстанавливается, а прерванные вызовы инструментов корректно закрываются. |

## Установка

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/). Чтобы команда `dreamteam` работала из любой папки,
установите DreamTeam как инструмент uv (из папки репозитория):

```bash
uv tool install --editable .
```

- uv кладёт команду `dreamteam` в свою папку для команд (`uv tool dir --bin`, обычно `~/.local/bin`). Если
  `dreamteam` после установки не находится, добавьте эту папку в PATH командой `uv tool update-shell` и
  откройте терминал заново.
- С `--editable` правки кода в папке репозитория действуют сразу. После изменения зависимостей в
  `pyproject.toml` или переноса папки репозитория переустановите: `uv tool install --editable . --force`.
- Удалить: `uv tool uninstall dreamteam`.

Без установки DreamTeam запускается из папки репозитория через uv: `uv sync`, затем `uv run dreamteam …`
(так же запускаются тесты, см. «Разработка»).

## Быстрый старт

```bash
dreamteam                                   # интерфейс в терминале (в стиле Claude Code)
dreamteam "Сделай игру змейка на Python"    # сразу новая сессия с этой целью
dreamteam serve                             # только веб-интерфейс (без терминала — по умолчанию)
```

В терминале `dreamteam` открывает [терминальный интерфейс](#терминальный-интерфейс). Если сервер ещё не
запущен, он стартует в том же процессе, поэтому веб-доска по адресу `http://127.0.0.1:8765` тоже доступна.
`dreamteam serve` запускает только веб-интерфейс. Откроется стартовая страница `http://127.0.0.1:8765`:

1. На вкладке **«Настройки» → «Модели и эндпоинты»** выберите провайдера и модель, укажите ключ (имя
   переменной окружения, например `ANTHROPIC_API_KEY`, или сам ключ) и нажмите «Проверить».
2. На вкладке **«Сессии»** нажмите **«Начать новую сессию»** и опишите цель: первая строка станет заголовком,
   остальные — описанием. Там же можно собрать стартовую команду. Рой создаст план и начнёт работу, а вы
   попадёте на доску сессии `/s/<id>/`.

Сессии и настройки хранятся в домашней папке DreamTeam: `~/DreamTeam` (её задают `--home` или переменная
`DREAMTEAM_HOME`). Там лежат `dreamteam.toml` с глобальными настройками и `sessions/<id>/` с данными, файлами
workspace и трейсами каждой сессии. Сессию можно сразу создать из командной строки:
`dreamteam serve --goal "Сделать CLI-утилиту для конвертации CSV в JSON с тестами" --title "CSV → JSON"`.

Команды:

| команда | что делает |
|---|---|
| `dreamteam ["цель"]` / `dreamteam tui` | терминальный интерфейс; `-c` — продолжить последнюю сессию, `-r [ID]` — выбрать или открыть сессию; для новой сессии: `--model`, `--agents`, `--team "architect, developer*2"`, `--max-agents`, `--budget`, `--title`, `--workspace ПАПКА` |
| `dreamteam -p "цель"` | без интерфейса: выполнить цель и вывести итог (`--output-format text/json/stream-json`, `--verbose`, `--timeout`, `-c`/`-r ID` — следующее указание существующей сессии, `--workspace ПАПКА` — папка новой сессии); текст из stdin добавляется к запросу |
| `dreamteam serve [HOME]` | стартовая страница, настройки, доски всех сессий и MCP (`--host`, `--port`, `--goal` и `--title` (с `--workspace ПАПКА`), `--no-browser`, `--no-console`); без терминала `dreamteam` запускает именно его |
| `dreamteam sessions` / `dreamteam status` | список сессий и запущен ли сервер |
| `dreamteam sessions rm ID [ID …]` | удалить сессии с доской, перепиской, файлами workspace и трейсами (спросит подтверждение; `--yes` — без вопроса); папка вне сессии (ваш проект или папка после `/cd`) остаётся на месте |
| `dreamteam console [--session ID]` | консольный чат с работающей сессией (`/help` — команды) |
| `dreamteam traces [Агент] [--session ID] [--id N] [--span N --context] [--status failed] [--json]` | трейсы агентов в терминале (с сервером и без него) |
| `dreamteam mcp` | DreamTeam как MCP-сервер по stdio (прокси к запущенному серверу или свой процесс) |
| `dreamteam sandbox [HOME]` | то же в Docker |
| `dreamteam init DIR` + `dreamteam run DIR` | прежний режим: один рой в папке проекта, без стартовой страницы |

Другую домашнюю папку этим командам (кроме `init` и `run`) передают через `--home ПАПКА`.

Ключи API не обязательно хранить в настройках: если указано `api_key_env`, ключ берётся из переменной окружения.
Для Claude подходит и профиль `ant auth login`.

### Папка сессии и существующий проект

По умолчанию сессия работает в своей папке `sessions/<id>/workspace`. Её можно перенести в любую другую папку
или направить рой на уже существующий проект.

Как подключить сессию к своему проекту:

1. Подготовьте репозиторий: закоммитьте свои правки или уберите их в `git stash` (с незакоммиченными изменениями
   и неотслеживаемыми файлами подключение не пройдёт, см. правила ниже). Агенты коммитят в текущую ветку, поэтому
   удобно сначала переключиться на отдельную: `git switch -c dreamteam/billing`.
2. Запустите новую сессию сразу в папке проекта:

   ```bash
   dreamteam --workspace ~/code/my-app "Покрой модуль billing тестами"
   ```

   Или перенесите уже идущую: в терминальном интерфейсе выполните `/cd ~/code/my-app` и ответьте «Да» на вопрос
   «Папка не пустая: агенты будут работать с её файлами и коммитить в текущую ветку…».
3. Агенты работают прямо с файлами проекта, их коммиты (под именами агентов) видны в `git log`. Пока сессия
   работает, не правьте файлы проекта сами: остановите её (`/stop`), закоммитьте свои правки и запустите снова.
4. Чтобы отключить сессию от проекта, выполните `/cd --default`: файлы и история проекта останутся на месте, а
   сессия вернётся в свою папку.

Команда `/cd` в терминальном интерфейсе:

- `/cd` без аргумента показывает папку текущей сессии: путь, своя она или папка проекта, существует ли;
- `/cd ПАПКА` переносит сессию (относительный путь и `~` раскрываются от текущей папки терминала, если сервер
  локальный). Перед переносом интерфейс спрашивает подтверждение;
- `/cd --default` возвращает сессию в её собственную папку.

То же умеют `/cd` в `dreamteam console`, MCP-инструмент `session_cd(session, path)` и
`POST /api/sessions/<id>/workspace` (`{"path": "<абсолютный путь>"}` или `{"default": true}`). Новую сессию можно
сразу создать в нужной папке: `--workspace ПАПКА` у `dreamteam`, `dreamteam -p` и `dreamteam serve --goal`,
`session_create(..., workspace=...)` в MCP или ключ `workspace` в `POST /api/sessions`.

Что происходит, зависит от целевой папки:

- **Папка пустая или её нет** — сессия **переезжает**: файлы, история git и MCP-серверы сессии переносятся туда,
  а старое место остаётся пустым (собственная папка сессии удаляется и при возврате создаётся заново).
  Исключение — сессия, подключённая к вашему проекту: файлы проекта остаются на месте, в новую папку переезжают
  только MCP-серверы сессии, и там создаётся новый репозиторий.
- **В папке уже есть файлы** (ваш проект) — сессия **подключается** к ней: агенты работают прямо с этими
  файлами, а их автокоммиты идут в **текущую ветку** репозитория. Прежняя папка сессии остаётся как была
  (путь к ней выводится), а MCP-серверы сессии переезжают в `<папка>/mcp/<имя>/`.

Правила безопасности для чужой папки:

- Если в репозитории есть незакоммиченные изменения или неотслеживаемые файлы (не из `.gitignore`; скрыть их
  настройкой `status.showUntrackedFiles` не выйдет), перенос отклоняется: агенты коммитят через `git add -A`,
  и ваши правки смешались бы с их коммитами. Сначала сделайте commit или `git stash`. Отклоняются и
  репозиторий в состоянии detached HEAD, и незавершённый merge, rebase, cherry-pick или revert (следующий
  коммит агента завершил бы его от своего имени), и подпапка репозитория (укажите его корень).
- Эти проверки повторяются при каждом запуске сессии, в том числе при возобновлении после перезапуска сервера:
  если, пока сессия стояла, вы оставили в проекте незакоммиченные правки или переключились на detached HEAD,
  сессия не запустится и скажет почему. Сделайте commit или `git stash` и запустите её снова. Если сессия
  подключилась к проекту с выключенным git, а потом git включили, проверка сработает при следующем запуске.
  Пока сессия работает, не правьте файлы проекта сами: следующий автокоммит агента заберёт и ваши правки.
  Остановите сессию (`/stop`), закоммитьте свои изменения и запустите её снова.
- Настройки вашего репозитория не меняются: DreamTeam не пишет в него `user.name`, `user.email`, `core.autocrlf`
  и другие ключи. Автор каждого коммита агента задаётся флагами самой команды git, ваши коммиты остаются вашими.
  Переводы строк в коммитах агентов следуют вашим настройкам (`core.autocrlf` и т. п.), как и в ваших коммитах.
- Если папка — не git-репозиторий, а git включён (`workspace.git`), DreamTeam создаёт в ней репозиторий:
  `git init`, `.gitignore` (если его нет) и начальный коммит с вашими файлами. Об этом сообщается в ответе.
- Если в папке уже есть `mcp/<имя>/` с тем же именем, что у MCP-сервера сессии, перенос отклоняется до любых
  изменений.
- Нельзя выбрать корень диска, домашнюю папку пользователя, домашнюю папку DreamTeam и папки других сессий,
  саму базу git-репозитория (папку `.git` или bare-репозиторий), общую библиотеку MCP-серверов, файл, папку
  внутри текущей папки сессии или содержащую её. Все проверки идут до первого изменения. Две сессии не могут
  работать в одной папке, даже если их переносят туда одновременно.
- Если вы согласились на перенос в пустую папку, а в ней тем временем появились файлы (или наоборот), перенос
  отклоняется: сессия сделает только то, на что вы согласились.
- Работающая сессия останавливается, переезжает и запускается снова с того же места. Если перенос сорвался
  посередине, файлы возвращаются обратно; файлы, которые появились в целевой папке во время переноса, не
  трогаются.
- Когда сессия уходит из вашего проекта (`/cd` в другую папку или `/cd --default`), файлы проекта остаются на
  месте, а с сессией уезжают только её MCP-серверы. Если агенты уже закоммитили их в ваш проект, DreamTeam
  закоммитит их удаление отдельным коммитом («Remove mcp/…»), чтобы репозиторий остался чистым. Если сделать
  такой коммит нельзя (detached HEAD, незавершённый merge, git выключен), ответ скажет, что закоммитить или
  вернуть (`git checkout -- mcp/…`).

Удаление сессии никогда не удаляет папку вне сессии: она остаётся на месте, и об этом пишут диалог удаления,
`dreamteam sessions rm` и `/delete`. Если папка пропала (её удалили, отключили диск), сессия не запустится и
подскажет, что делать: вернуть папку или выполнить `/cd` в другую (`/cd --default` — в собственную).
Для этого подходит и `dreamteam console --session ID`: к остановленной сессии без папки консоль подключается,
чтобы её можно было перенести.
На стартовой странице у каждой сессии видна её папка с пометкой «своя папка», «папка проекта» или «перенесена»
и предупреждение, если папки нет; на доске сессии путь показан на вкладке «Файлы». Менять папку из
веб-интерфейса нельзя, только командой `/cd`, через MCP или REST.

Сессию `main` бывшего проекта (`dreamteam run`) перенести нельзя.

### Подключение к Claude Code

Если DreamTeam запущен, подключитесь по HTTP:

```bash
claude mcp add --transport http dreamteam http://127.0.0.1:8765/mcp
```

Без запущенного сервера Claude Code может сам поднять DreamTeam через stdio (нужна команда `dreamteam` в PATH,
см. [«Установка»](#установка)). Если сервер уже запущен, команда станет прокси к нему:

```bash
claude mcp add dreamteam -- dreamteam mcp
```

Через `/mcp` доступны инструменты сессий: `sessions_list`, `session_create(title, goal, ..., workspace)`,
`session_start`, `session_stop` и `session_cd(session, path)` (перенос в другую папку, `path="default"` — в
собственную). Остальные инструменты работают внутри сессии, её задаёт параметр `session="<id>"`; по умолчанию
выбирается работающая сессия. Подключиться к одной сессии напрямую можно по адресу `http://127.0.0.1:8765/s/<id>/mcp`.

По умолчанию Claude Code действует как пользователь роя: задаёт цель, смотрит доску, пишет агентам, одобряет MCP,
читает трейсы (`agent_traces`) и ждёт сообщений через `wait_for_events`. Чтобы работать внутри роя, нужно вызвать
`join_swarm(role=...)` и затем передавать `as_agent="<имя>"`: так можно брать задачи, писать файлы, выполнять
команды и создавать MCP.

### Песочница Docker

```bash
dreamteam sandbox ~/DreamTeam --goal "..."
```

Команда собирает образ `dreamteam:latest` и запускает DreamTeam в контейнере. Домашняя папка монтируется в `/swarm`,
стартовая страница доступна на `127.0.0.1:8765`. Альтернатива: `SWARM_DIR=~/DreamTeam docker compose up --build`.
Локальные модели (Ollama, vLLM) из контейнера доступны по адресу `http://host.docker.internal:<порт>`.
В контейнер монтируется только домашняя папка, поэтому сессии, перенесённые командой `/cd` в папку вне неё, в
песочнице не запустятся: `dreamteam sandbox` перечисляет их при старте. Перед запуском верните такие сессии в
домашнюю папку (`/cd --default` или `/cd` в папку внутри неё: такие папки находятся и в контейнере).

## Трейсы агентов

Откройте вкладку **«Трейсы»** на доске сессии или нажмите «📈 Трейсы» в окне агента.

* Слева список пробуждений агентов с фильтрами по агенту и статусу (`done`, `error`, `step_limit`, `refusal`,
  `interrupted`, «только с ошибками»).
* Справа сводка трейса: шаги, вызовы LLM, инструменты, ошибки, токены (вход/выход/кэш), стоимость и связанные задачи.
  Ниже водопад шагов на шкале времени.
* По клику шаг раскрывается.
  * У вызова LLM видны модель, причина остановки, токены, стоимость, мысли, ответ и вызовы инструментов, а кнопка
    «Контекст запроса» показывает системный промпт, инструменты и все сообщения, которые видела модель.
  * У инструмента видны полные аргументы и результат. Если модель получила урезанный результат, это помечено.
* «📊 Статистика» показывает вызовы, ошибки и среднее время по инструментам и моделям.
* «⬇ Экспорт» выгружает трейс в JSON (с контекстами или без), а все трейсы агента — в JSONL.

То же доступно без UI:

* REST сессии (пути от `/s/<id>`): `/api/traces`, `/api/traces/<n>`, `/api/spans/<n>`, `/api/spans/<n>/context`,
  `/api/traces/stats`, `/api/traces/<n>/export`, `/api/agents/<имя>/traces.jsonl`.
* Терминал: `dreamteam traces "Анна Смирнова" --status failed`.
* MCP: `agent_traces(agent=..., trace_id=..., span_id=..., context=true)`.

Настройки находятся в секции `[tracing]`: `enabled`, `max_payload_chars` (лимит одного поля) и `retention_days`
(через сколько дней удалять старые трейсы; `0` — хранить всегда).

## Конфигурация (`dreamteam.toml`)

Глобальные настройки лежат в `<home>/dreamteam.toml`. Их удобнее менять на вкладке «Настройки»: страница проверяет
значения перед сохранением и хранит предыдущую версию в `dreamteam.toml.bak`. Ручная правка файла тоже работает,
но комментарии при сохранении из UI не сохраняются; правка файла при работающем сервере подхватывается. При создании
сессии можно переопределить язык, стартовую команду (роли и число агентов), бюджет, профиль модели, число шагов и
одобрение MCP. Эти значения хранятся в `sessions/<id>/session.json`; остальное берётся из глобальных настроек.
У уже созданной сессии кнопка ⚙ на её странице меняет бюджет и максимум агентов, а также её собственные лимиты
фоновых процессов (на участника, на сессию, предел жизни, потоки вычислений) и параметры агентов (шаги за
пробуждение, окно контекста, лимит вывода инструмента, напоминание простаивающим, параллельные вызовы LLM). Пустое
поле означает значение из общих настроек; изменения применяются сразу, без перезапуска. У сессии `main` (и у доски
`dreamteam run`) ⚙ меняет только бюджет и максимум агентов: остальное задаётся в общих настройках.
Цель задаётся при создании сессии (ключ `goal` в `[swarm]` используется только в режиме `dreamteam run` и в сессии
`main` бывшего проекта).

```toml
[swarm]                  # значения по умолчанию для новых сессий
name = "Мой рой"
language = "ru"          # язык промптов агентов: ru | en
start_agents = 3         # сколько агентов стартует
max_agents = 8           # максимум ИИ-агентов (нанимают новых сами; участники через MCP не считаются)
max_cost_usd = 5.0       # бюджет; при исчерпании — пауза
starting_roles = []      # стартовая команда по порядку: ["architect", "developer", "developer", "tester"]
independent_review = true # задачу агента принимает другой участник (или вы, если больше некому)

[[roles]]                # своя роль в каталоге (встроенную меняют, указав её id: name = "tester")
name = "Дизайнер"
description = "Ты проектируешь интерфейсы: макеты, тексты экранов, сценарии пользователя."
model = ""               # профиль модели для этой роли ("" — по умолчанию)

[agents]
default_model = "default"
max_steps_per_turn = 40
context_tokens = 120000  # порог сжатия истории агента в резюме

[shell]                  # консоль агентов (полный список — на вкладке «Настройки»)
timeout = 120            # столько секунд вызов ждёт команду; дальше она работает как фоновый процесс
foreground_max = 180     # ИИ-агент ждёт команду не дольше этого, какой бы тайм-аут он ни задал
max_jobs = 16            # фоновых процессов в сессии (0 — без фоновых процессов)
job_max_minutes = 480    # сколько живёт процесс, запущенный в фоне намеренно (0 — без предела)

[models.default]         # Claude
provider = "anthropic"
model = "claude-opus-5-5"
api_key_env = "ANTHROPIC_API_KEY"
effort = "medium"
fallbacks = "default"           # серверный fallback при отказе модели (beta)
thinking_mismatch = "drop_block" # не падать при изменении префикса диалога (beta)
max_tokens = 16000
max_tokens_ceiling = 32000      # после ответа, обрезанного по лимиту, лимит удваивается до этого (по умолчанию 2 × max_tokens)

[models.local]           # Ollama / vLLM / OpenRouter — любой OpenAI-совместимый API
provider = "openai"
base_url = "http://localhost:11434/v1"
model = "qwen3:32b"
api_key = "ollama"
input_price = 0
output_price = 0

[mcp]
require_approval = false
[mcp.external.fetch]     # внешние MCP-серверы для роя
command = ["uvx", "mcp-server-fetch"]
description = "Загрузка веб-страниц"

[tracing]
enabled = true           # трейсы агентов
max_payload_chars = 200000
retention_days = 0       # 0 — хранить всегда

[server]
host = "127.0.0.1"
port = 8765
resume_sessions = true   # возобновлять сессии, которые работали при остановке
```

Для цен известных моделей Claude используются встроенные значения. Для остальных моделей укажите
`input_price` и `output_price` в долларах за 1M токенов. Если провайдер сам сообщает стоимость (как OpenRouter), берётся она.

### Роли и стартовая команда

В DreamTeam есть каталог ролей: универсал, разработчик, тестировщик, ревьюер, аналитик, архитектор, технический
писатель и исследователь. У каждой роли есть описание, которое попадает в системный промпт агента при найме, а
также свои инструкции и профиль модели, если они заданы. Каталог настраивается на вкладке «Настройки» → «Роли»
(или в `[[roles]]`). Там можно поправить встроенную роль, скрыть её или добавить свою. Правка доходит только до
агентов, нанятых после неё: промпты уже работающих агентов не меняются. Агенты нанимают по каталогу
(`hire_agent` с ролью из него может обойтись без инструкций), а вы — командой `/hire Роль` или кнопкой найма на
доске. **Стартовая команда** — это роли агентов, с которыми начинается сессия. Её задают так:

- в окне новой сессии или в настройках («Роль ×N», строки по порядку);
- флагом `--team "architect, developer*2, tester"`;
- командой `/team` в терминале.

Агенты сверх списка становятся универсалами.

## Терминальный интерфейс

`dreamteam` в терминале выглядит и управляется как Claude Code:

- **Первое сообщение без сессии** становится целью новой сессии: первая строка — заголовок, остальные
  (`Alt+Enter` — новая строка) — описание. Рой собирает команду и начинает работу.
  Дальше сообщения уходят текущему адресату. Он показан в заголовке рамки: это агент, который написал вам
  последним, иначе ответственный за планирование, иначе все. `@Имя текст` пишет конкретному агенту и делает
  его адресатом, `@all` пишет всем.
- **Лента.** Вызовы инструментов агентов выглядят как `⏺ Анна Смирнова · task_claim(task_id=3)` с результатом
  `⎿` под ними. Сообщения вам выводятся целиком в markdown, задачи — списком дел `☐ ◐ ◑ ☒`, цель — рамкой.
  `Shift+Tab` переключает подробность: тихо, обычно (по умолчанию) или подробно с мыслями агентов и
  результатами инструментов. `Ctrl+O` включает подробный режим.
- **Спиннер** `✻ Совещаются… (12s · ↑ 4.2k ↓ 310 · $0.12 · esc — пауза)` виден, пока агенты работают.
  `Esc` ставит рой на паузу, `/pause` снимает её.
- **Команды** (`/` открывает подсказки): `/new [цель]`, `/sessions` (`Del` в списке удаляет сессию),
  `/resume ID`, `/delete [ID]`, `/cd [путь | --default]`, `/goal`, `/board`,
  `/task N`, `/agents`, `/roles [роль]`, `/jobs [jN | stop jN]`, `/team [роль*N, …]`, `/to Имя`,
  `/hire Роль [| инструкции]`,
  `/trace [Имя | N]`, `/span N [ctx]`, `/files [путь]`, `/cat путь`, `/cost`, `/status`, `/model [профиль]`,
  `/pause`, `/wrapup [off]`, `/budget N`, `/max N`, `/approve имя|N`, `/reject имя|N`, `/stop`, `/web`, `/settings`, `/verbose`,
  `/lang ru|en`, `/clear`, `/exit`.
- **Ревью.** Задача, которую рой отдал на ревью вам, видна как `◑ #3 … ждёт вашего ревью`. `/approve 3`
  принимает её, `/reject 3 что исправить` возвращает исполнителю. На веб-доске для этого есть кнопки в карточке
  задачи, а перетаскивание из «Ревью» в «Готово» тоже принимает задачу.
- **Фоновые процессы агентов.** Пока они работают, в строке статуса видно `процессы N`, а у агента в `/agents` —
  `⚙N`. `/jobs` показывает их список (и закончившиеся за последний час), `/jobs j3` — вывод процесса,
  `/jobs stop j3` — останавливает его вместе со всем, что он запустил. `Esc` и `/pause` их не останавливают.
- **Режим завершения.** `/wrapup` (на веб-доске — кнопка «Завершать» рядом с «Пауза») просит команду закругляться:
  каждый агент один раз получает об этом уведомление, а каждое пробуждение напоминает, что новых вычислений не
  начинать и свои задачи завершить с тем, что есть. Новые фоновые процессы в этом режиме не запускаются: команда,
  не уложившаяся в свой тайм-аут, обрывается, а уже запущенные процессы работают дальше. `/wrapup off` выключает
  режим; новая цель или возврат цели в работу выключают его сами.
- **`!команда`** выполняет команду в папке сессии (в том числе после `/cd`). Это работает, когда сервер локальный.
- **`/cd`** показывает папку сессии или переносит сессию в другую папку, в том числе в ваш проект
  (подробнее — [Папка сессии и существующий проект](#папка-сессии-и-существующий-проект)).
- **Клавиши:**
  - `Enter` — отправить;
  - `Alt+Enter`, `Ctrl+J` или `\` в конце строки — новая строка;
  - `↑/↓` — история;
  - `Tab` — дополнить;
  - `Ctrl+L` — очистить экран;
  - `Ctrl+C` дважды или `Ctrl+D` — выход;
  - `?` — справка по клавишам.
- **Одобрение MCP.** Когда агент создаёт MCP-сервер, а в настройках включено одобрение, поле ввода
  сменяется диалогом «разрешить / отклонить».

Если сервер для домашней папки уже запущен (`dreamteam serve`), интерфейс подключается к нему. Иначе сервер
стартует в том же процессе, а при выходе сессии останавливаются; `dreamteam -c` продолжит последнюю.
В Git Bash (mintty) запускайте `winpty dreamteam` или пользуйтесь Windows Terminal / PowerShell.

Неинтерактивный режим для скриптов:

```bash
dreamteam -p "Напиши скрипт, который считает строки кода в репозитории" --output-format json
cat error.log | dreamteam -p "Найди причину ошибки" -c
```

Вопросы агентов к пользователю в этом режиме получают ответ «решите сами», а задачи, ждущие вашего ревью,
принимаются автоматически с пометкой, что их никто не проверял (`--no-auto-reply` отключает и то и другое).
Фоновые процессы, которые ещё работают к концу (например, dev-сервер), перечислены в поле `jobs` результата
`--output-format json`. Сервер, запущенный в том же процессе, останавливает их вместе с сессией. Если сервер
уже был запущен отдельно, процессы работают до остановки сессии, и текстовый режим сообщает о них в stderr.
Коды выхода:

- `0` — цель достигнута;
- `2` — исчерпан бюджет;
- `3` — истёк `--timeout`;
- `1` — ошибка;
- `130` — Ctrl+C.

## Команды консоли

`@Имя Фамилия текст` — написать агенту, `/chat Имя` — диалоговый режим, `/all текст` — написать всем,
`/goal Заголовок | описание`, `/task Заголовок | цель`, `/board`, `/agents`, `/status`,
`/show N` (задача и её обсуждение), `/comment N текст`, `/hire Роль [| инструкции]`, `/pause`, `/resume`,
`/wrapup [off]` (режим завершения),
`/budget 10`, `/max 6`, `/approve имя|N`, `/reject имя|N` (MCP-сервер или задача на ревью),
`/jobs [jN | stop jN]` (фоновые процессы агентов: список, вывод одного, остановка),
`/trace [Имя | N]` (трейсы), `/span N [ctx]` (шаг трейса
и контекст запроса), `/session` (текущая сессия), `/cd [путь | --default]` (папка сессии; перенос спрашивает
подтверждение `y/N`, `--yes` — без вопроса).
Консоль подключается к работающей сессии: `dreamteam console` (или `dreamteam console --session 003-snake`).
Это простой построчный клиент для терминалов, где не работает [терминальный интерфейс](#терминальный-интерфейс).

## Инструменты агентов

Набор инструментов минимален: только взаимодействие с роем и консоль. Всё остальное агенты пишут себе
сами в виде MCP-серверов.

* Доска: `board`, `task_get`, `task_create`, `task_claim`, `task_update`, `task_complete`, `task_review`,
  `task_comment`, `task_discussion`.
* Общение: `send_message`, `read_messages`.
* Команда: `agents`, `hire_agent`, `retire_agent`, `update_notes` (блокнот, который переживает сжатие контекста),
  `wait`, `goal_complete`.
* Триггеры: `trigger_create`, `trigger_list`, `trigger_delete`.
* Файлы и консоль: `read_file`, `write_file`, `edit_file`, `list_files`, `lock_file`, `shell` (с `background` —
  команда сразу уходит в фон).
* Фоновые процессы: `jobs` (список, состояние и вывод процесса), `job_stop` (остановить процесс и всё, что он
  запустил).
* MCP: `mcp_create`, `mcp_list`, `mcp_tools`, `mcp_call`.

Шаблон MCP-сервера, который пишут агенты (mcp 2.x):

```python
from mcp.server.mcpserver import MCPServer

mcp = MCPServer("csv_tools")

@mcp.tool()
def count_rows(path: str) -> int:
    """Count data rows in a CSV file."""
    ...

if __name__ == "__main__":
    mcp.run()
```

## Как это устроено

```
 Стартовая страница ─REST+WS─► Launcher (SessionManager, настройки, /mcp)
                                  │  /s/<id>/…  — доска, REST, WS и MCP одной сессии
 Веб-доска / консоль ──REST+WS──┐ ▼                       ┌── агенты-LLM (ReAct, свой asyncio-таск) ── Tracer
 Claude Code ───────────MCP─────┤   Swarm сессии          ├── внешние участники через MCP (join_swarm) ── Tracer
                                └─► Board · Mailbox · Workspace(git) · Triggers · MCPForge · Budget · Tracer
                                     └── SQLite сессии: задачи, обсуждения, сообщения, уведомления, история агентов,
                                         архив истории, трейсы и спаны, журнал событий
```

* Агент спит, пока для него нет событий. Его будят сообщения, назначения, посты в обсуждениях,
  разблокированные задачи и триггеры. При пробуждении агент получает сводку: что произошло, цель роя,
  свои задачи, свободные задачи и свой блокнот. Дальше идёт цикл ReAct: LLM, инструменты, LLM… пока агент не вызовет `wait`.
* История агента ведётся только на дописывание: thinking-блоки Claude привязаны к точному префиксу диалога, и
  ради этого же работает кэш промптов. Системный промпт фиксируется при найме, набор инструментов у агента
  постоянный, а MCP-инструменты вызываются через `mcp_call`. Когда контекст переполняется, история сжимается в резюме.
  Только в этот момент агент из уже идущей сессии получает новые инструменты DreamTeam (например, `jobs` и
  `job_stop`): смена набора тогда ничего не ломает. До этого фоновые процессы работают и у него: команда уходит в
  фон по тайм-ауту, а `kill j3` в консоли останавливает процесс.
* Каждое изменение пишется в журнал событий. Из него строятся живые обновления UI, лента и проверка триггеров.
* Контракт модулей описан в [docs/SPEC.md](docs/SPEC.md).

Идеи взяты у Claude Code Agent Teams (общий список задач, захват задач, почтовые ящики), Gas Town / Beads
(состояние в git, продолжение после сбоя), CAMEL Workforce и Magentic-One (каналы задач, перепланирование),
MetaGPT (подписка на события), Strands Swarm (защита от зацикливания), Letta (блокнот, переживающий сжатие),
Alita (агенты сами создают MCP и складывают их в библиотеку), A2A (жизненный цикл задач с ожиданием ввода)
и blackboard-архитектуры (агенты сами вызываются на задачи).

## Безопасность

* Агенты выполняют команды и код MCP-серверов с правами пользователя, который запустил рой. Для недоверенных
  задач используйте `dreamteam sandbox` (Docker).
* Фоновые процессы агентов работают с теми же правами в папке сессии. Они не переживают свою сессию: её
  остановка, удаление или перенос (`/cd`) останавливают их вместе со всем, что они запустили (в Windows — Job
  Object, в Linux и macOS — группа процессов и сторожевой процесс; так же и после сбоя сервера). Их вывод
  хранится в `.scratch/<агент>/jobs/`. В песочнице Docker порты, которые открывают агенты (dev-серверы), наружу
  не публикуются.
* Сессия, подключённая командой `/cd` к вашему проекту, правит его файлы и коммитит в текущую ветку. Перед
  переносом переключитесь на отдельную ветку, если не хотите видеть коммиты агентов в основной.
* Секреты (`*_API_KEY`, `*_TOKEN`, `*SECRET*`, …) не передаются в консоль агентов и их MCP-серверы,
  если вы явно не разрешили их в `shell.pass_env`.
* Хаб по умолчанию слушает только `127.0.0.1`. Не открывайте его в сеть без обратного прокси с авторизацией.
* Защита от DNS-rebinding и межсайтовых запросов действует при любом адресе привязки (включая `0.0.0.0` в Docker):
  по IP и `localhost` доступ есть всегда, другие имена хостов перечислите в `DREAMTEAM_ALLOWED_HOSTS=board.example.com`.
  `DREAMTEAM_PUBLIC_URL` задаёт адрес доски, который видят пользователи (его выставляет `dreamteam sandbox`).
* `docker compose up --build` отправляет в Docker только исходники (`.dockerignore`): ни `.venv`, ни `.git`, ни папки
  роёв с их базами и `dreamteam.toml` с ключами в образ не попадают.
