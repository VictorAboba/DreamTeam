# Установка и быстрый старт

## Установка

Нужны Python 3.11+, [uv](https://docs.astral.sh/uv/) и git. Чтобы команда `dreamteam` работала из любой папки,
установите DreamTeam как инструмент uv:

```bash
uv tool install git+https://github.com/VictorAboba/DreamTeam.git
```

- uv кладёт команду `dreamteam` в свою папку для команд (`uv tool dir --bin`, обычно `~/.local/bin`). Если
  `dreamteam` после установки не находится, добавьте эту папку в PATH командой `uv tool update-shell` и
  откройте терминал заново.
- Обновить до последней версии: `uv tool upgrade dreamteam` (с 0.1.x — сначала прочитайте
  [Обновление до 0.2.0](#обновление-до-020)). Удалить: `uv tool uninstall dreamteam`.

Чтобы менять код, склонируйте репозиторий и установите его из папки репозитория с `--editable`: правки кода
тогда действуют сразу.

```bash
uv tool install --editable .
```

После изменения зависимостей в `pyproject.toml` или переноса папки репозитория переустановите:
`uv tool install --editable . --force`. Без установки DreamTeam запускается из папки репозитория через uv:
`uv sync`, затем `uv run dreamteam …`. Так же запускаются тесты, см. [CONTRIBUTING.md](../../CONTRIBUTING.md).

### Обновление до 0.2.0

В 0.2.0 появились [групповые задачи](features.md) и новый набор инструментов агентов. Сессии, в которых уже
работали агенты прежней версии (это почти все сессии 0.1.x), 0.2.0 не открывает, и перевести их на новую версию
нельзя.

- **Перед обновлением** завершите сессии, которые вам ещё нужны, или экспортируйте их и сохраните папку:
  `dreamteam export ПАПКА --include sessions` (для одной сессии добавьте `--session ID`; см.
  [Перенос на другой компьютер](transfer.md)). В 0.1.0 команды `dreamteam export` нет: там завершите сессии или
  обновитесь и экспортируйте их уже в 0.2.0 — она экспортирует такие сессии с предупреждением.
- **После обновления** такие сессии остаются в списке с пометкой, что это сессии прежней версии: в
  `dreamteam sessions`, на стартовой странице («Прежняя версия») и в `/sessions` терминального интерфейса
  («прежняя версия»). Почему сессия не открывается, объясняет её карточка на стартовой странице, а в списке
  терминального интерфейса — Enter. Такую сессию можно удалить и экспортировать, но нельзя открыть, запустить или
  возобновить, а импорт 0.2.0 её отклоняет. Если такая сессия — последняя по времени, `dreamteam -c` сообщает об
  этом и ничего не открывает: начните новую.
- **Сессия, в которой ещё не работал ни один агент** (например, ни разу не запущенная), открывается как обычно.
- **Чтобы снова открыть сессию прежней версии**, импортируйте её экспорт в отдельную домашнюю папку DreamTeam 0.1.1
  (в 0.1.0 нет ни экспорта, ни импорта, а 0.1.1 открывает и сессии 0.1.0). uvx запускает 0.1.1, не трогая
  установленную 0.2.0, например:

  ```bash
  uvx --from "git+https://github.com/VictorAboba/DreamTeam.git@v0.1.1" dreamteam import ПАПКА --home НОВАЯ_ПАПКА
  uvx --from "git+https://github.com/VictorAboba/DreamTeam.git@v0.1.1" dreamteam --home НОВАЯ_ПАПКА
  ```

  `НОВАЯ_ПАПКА` — новая пустая папка, а не домашняя папка, с которой работает 0.2.0. Экспортируйте только сессии (`--include sessions`), а модели настройте в новой домашней папке заново, как после
  первой установки: настройки, которые уже сохранила 0.2.0, версия 0.1.x может не прочитать. По той же причине не
  возвращайтесь на 0.1.x в домашней папке, с которой работала 0.2.0.
- **Сессию `main` бывшего проекта** нельзя ни экспортировать, ни удалить из интерфейса: завершите её работу ещё до
  обновления. После него её можно только удалить вручную: файл `<домашняя папка>/.dreamteam/swarm.db` вместе с
  файлами `-wal` и `-shm` (путь назван в её сообщении).

## Быстрый старт

```bash
dreamteam                                   # интерфейс в терминале (в стиле Claude Code)
dreamteam "Сделай игру змейка на Python"    # сразу новая сессия с этой целью
dreamteam serve                             # только веб-интерфейс (без терминала — по умолчанию)
```

В терминале `dreamteam` открывает [терминальный интерфейс](terminal.md). Если сервер ещё не
запущен, он стартует в том же процессе, поэтому веб-доска по адресу `http://127.0.0.1:8765` тоже доступна.
`dreamteam serve` запускает только веб-интерфейс. Откроется стартовая страница `http://127.0.0.1:8765`:

1. На вкладке **«Настройки» → «Модели и эндпоинты»** выберите провайдера и модель, укажите ключ (имя
   переменной окружения, например `ANTHROPIC_API_KEY`, или сам ключ) и нажмите «Проверить».
2. На вкладке **«Сессии»** нажмите **«Начать новую сессию»** и опишите цель: первая строка станет заголовком,
   остальные — описанием. Там же можно собрать стартовую команду или выбрать сохранённую. Отметьте **«Сначала
   уточнить цель»**, если в цели есть открытые вопросы: тогда планировщик спросит вас о них до плана, а остальные
   агенты подождут ([уточнение цели](features.md)). Рой создаст план и начнёт работу, а вы попадёте на доску сессии
   `/s/<id>/`.

Сессии и настройки хранятся в домашней папке DreamTeam: `~/DreamTeam` (её задают `--home` или переменная
`DREAMTEAM_HOME`). Там лежат `dreamteam.toml` с глобальными настройками и `sessions/<id>/` с данными, файлами
workspace и трейсами каждой сессии. Сессию можно сразу создать из командной строки:
`dreamteam serve --goal "Сделать CLI-утилиту для конвертации CSV в JSON с тестами" --title "CSV → JSON"`.

Команды:

| команда | что делает |
|---|---|
| `dreamteam ["цель"]` / `dreamteam tui` | терминальный интерфейс; `-c` — продолжить последнюю сессию, `-r [ID]` — выбрать или открыть сессию; для новой сессии: `--model`, `--agents`, `--team "architect, developer*2"` или `--team ИМЯ` (сохранённая команда), `--max-agents`, `--budget`, `--title`, `--workspace ПАПКА`, `--copy-from ПАПКА\|ZIP` (сессия работает с [копией этих файлов](projects.md#работа-с-копией-файлов)), `--clarify` / `--no-clarify` (уточнение цели для сессий, которые создаёт это окно); сессия прежней версии (в ней уже работали агенты 0.1.x) не открывается: если она последняя, `-c` сообщает об этом и ничего не создаёт, а `-r ID` такой сессии объясняет, почему она не открывается ([Обновление до 0.2.0](#обновление-до-020)) |
| `dreamteam -p "цель"` | без интерфейса: выполнить цель и вывести итог (`--output-format text/json/stream-json`, `--verbose`, `--timeout`, `-c`/`-r ID` — следующее указание существующей сессии (для сессии прежней версии — код выхода 1 и объяснение, почему она не открывается), `--workspace ПАПКА` — папка новой сессии, `--copy-from ПАПКА\|ZIP` — копия файлов в ней, `--clarify` — только с `--no-auto-reply`); текст из stdin добавляется к запросу |
| `dreamteam serve [HOME]` | стартовая страница, настройки, доски всех сессий и MCP (`--host`, `--port`, `--goal` и `--title` (с `--workspace ПАПКА`, `--copy-from ПАПКА\|ZIP`, `--clarify`), `--no-browser`, `--no-console`); без терминала `dreamteam` запускает именно его |
| `dreamteam sessions` / `dreamteam status` | список сессий и запущен ли сервер; сессии прежней версии помечены |
| `dreamteam sessions rm ID [ID …]` | удалить сессии с доской, перепиской, файлами workspace и трейсами (спросит подтверждение; `--yes` — без вопроса); папка вне сессии (ваш проект или папка после `/cd`) остаётся на месте; сессии прежней версии тоже удаляются, кроме сессии `main` бывшего проекта: её сообщение называет файл, который надо удалить вручную |
| `dreamteam export ПАПКА` | выгрузить настройки, скиллы, MCP-серверы и сессии в папку для другого компьютера или резервной копии (`--include settings,skills,mcp,sessions`, `--session ID`, `--dry-run`); ключи API и значения `env` остаются здесь, см. [Перенос на другой компьютер](transfer.md) |
| `dreamteam import ПАПКА` | добавить из такой папки новое и переписать изменённое; то, чего нет в экспорте, не удаляется (покажет план и спросит подтверждение; `--yes` или `-y` — без вопроса, `--dry-run` — только план, `--include`, `--session ID`); пока DreamTeam работает с этой домашней папкой, импорт отклоняется |
| `dreamteam console [--session ID]` | консольный чат с работающей сессией (`/help` — команды) |
| `dreamteam traces [Агент] [--session ID] [--id N] [--span N --context] [--status failed] [--json]` | трейсы агентов в терминале (с сервером и без него) |
| `dreamteam mcp` | DreamTeam как MCP-сервер по stdio (прокси к запущенному серверу или свой процесс) |
| `dreamteam sandbox [HOME]` | то же в Docker |
| `dreamteam init DIR` + `dreamteam run DIR` | прежний режим: один рой в папке проекта, без стартовой страницы |

Другую домашнюю папку этим командам (кроме `init` и `run`) передают через `--home ПАПКА`.

Ключи API не обязательно хранить в настройках: если указано `api_key_env`, ключ берётся из переменной окружения.
Для Claude подходит и профиль `ant auth login`.
