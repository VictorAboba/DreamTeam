# Самоаудит безопасности, ноябрь 2026

[English](../../en/audits/2026-11-self-audit.md) · **Русский** · [К документации](../README.md)

2 ноября 2026 года рой DreamTeam проверил исходники самого DreamTeam. Потом каждую его находку независимо
перепроверили по коду. Здесь собраны постановка, что рой нашёл, что из этого оказалось правдой и что исправлено.

## Коротко

- В настоящем коде нашлись одна серьёзная уязвимость (F-03, побег из песочницы через git-конфиг рабочей папки),
  пять средних (одну из них, M-1, рой пропустил) и одиннадцать низких. Все исправлены в
  [#33](https://github.com/VictorAboba/DreamTeam/pull/33) и [#36](https://github.com/VictorAboba/DreamTeam/pull/36).
  F-19 исправлена частично, остальное в ней — задокументированное ограничение. См.
  [advisory](https://github.com/VictorAboba/DreamTeam/security/advisories).
- Все три закладки, заранее засеянные в проверяемую копию, рой нашёл; первую — через 5 минут.
- Из 27 находок роя настоящими оказались 13 (48 %). Остальные — дубли, поведение «так задумано» или справка.
  Серьёзность рой чаще завышал: 11 находок понижено, 2 повышено.
- Шесть проблем рой пропустил; все нашлись при внешней проверке.

Рой описал все три с верными `файл:строка` и рабочими PoC, но в итоговом резюме написал «закладок не
обнаружено»: подозрительный код он нашёл, а намеренность не распознал.

## Что исправлено

[#33](https://github.com/VictorAboba/DreamTeam/pull/33), коммит `363d431`:

- **F-03.** Git, который запускает сам DreamTeam (автокоммиты, проверка папки проекта, коммиты `/cd`), никогда
  не исполняет то, что задаёт репозиторий: хуки, `core.fsmonitor`, фильтры, textconv и merge-драйверы, ssh и
  помощники учётных данных — из `.git/config`, подключаемых файлов и подмодулей. Он работает с окружением без
  секретов и без сети; в сессии без сети в Docker и на Linux — так же, как команды агентов. Файлы обязательного
  фильтра, который задан только в конфиге самого репозитория (git-crypt, `git-lfs --local`), DreamTeam не
  коммитит: их коммитят своим git.
- **M-1.** Хаб на адресе не loopback требует токен (`DREAMTEAM_HUB_TOKEN`) и без него не запускается.
  `dreamteam sandbox` создаёт токен при каждом запуске и держит его на хосте вне смонтированных папок; контейнер
  получает только SHA-256 токена. `console`, `tui`, `mcp`, `status` и `serve` передают токен сами.
  `docker compose up` и `docker run` образа теперь требуют `DREAMTEAM_HUB_TOKEN`, см. [песочницу](../sandbox.md).

[#36](https://github.com/VictorAboba/DreamTeam/pull/36), коммит `ad3de3c`:

- **F-04, F-05, M-6.** `write_file` и `edit_file` отказываются менять файл с другой жёсткой ссылкой; проверка идёт
  до работы и ещё раз по открытому файлу. Перед самым открытием запись заново проверяет папку файла и отказывает,
  если та теперь ведёт за рабочую папку или файл стал ссылкой. Папка логов задачи используется, только пока она
  внутри рабочей папки и не является ссылкой.
- **F-06.** Пути UNC и пути устройств Windows вне рабочей папки отклоняются до любого обращения к ним; цикл
  триггеров проверяет файлы в отдельном потоке.
- **F-19.** Контейнер песочницы работает с `no-new-privileges`: никакая программа в нём не получает права через
  бит set-user-ID. Команды сессий с сетью по-прежнему выполняются в контейнере от root: на Linux с rootful Docker
  для недоверенных целей запускайте песочницу без сети или используйте rootless Docker, Docker Desktop или
  `userns-remap`.

[#36](https://github.com/VictorAboba/DreamTeam/pull/36), коммит `3a214b4`:

- **F-22 и самоодобрение MCP-сервера агентом.** Хаб с токеном требует его и с loopback, поэтому команды агентов в
  песочнице не могут действовать через API от имени пользователя.
- **M-2, F-14.** С `require_approval` одобрение относится к одному снимку MCP-сервера: SHA-256 по команде запуска,
  зависимостям и `server.py`. Сервер запускает именно этот снимок, а `mcp_approve` отказывает, если дайджест
  другой.
- **M-4, F-10.** Фильтр секретов покрывает больше имён; учётные данные в URL удаляются из того, что получают
  агенты, и маскируются в логах установщиков.
- **M-5.** Проверка настроек отправляет сохранённый ключ только на его собственный эндпоинт.
- **M-3.** `install_proposals = false` распространяется и на скиллы `claude-project`.
- **F-08.** Доска и её WebSocket принимают только собственный origin хаба, `DREAMTEAM_PUBLIC_URL` или имя из
  `DREAMTEAM_ALLOWED_HOSTS`.
- **F-11, F-12, F-26.** GitHub Actions закреплены по коммиту; образ ставит зависимости из `uv.lock` с хешами и
  больше не доверяет git любому репозиторию.

## Точность роя

- **Полнота.** Засеянные закладки — 3 из 3. В настоящем коде рой нашёл главную проблему (F-03) и правильно
  поставил ей high, но её худший сценарий (Docker без сети) недооценил.
- **Шум.** 14 из 27 находок — дубли, «так задумано» или справка. Типичная ошибка — не прочитать
  [спецификацию](../../SPEC.md), где поведение описано как намеренное (F-07, F-09, F-18).
- **Пропуски.** 6 проблем, в том числе одна medium (M-1). Рой написал «порт только на 127.0.0.1», проверив, как
  публикуется порт, но не адрес, на котором хаб слушает внутри контейнера.
- **Ложное «чисто».** Кроме «закладок нет», рой назвал проверенным и чистым ещё несколько мест, где проблемы были:
  «Guard отклоняет чужой `Origin`» (кроме `*.dreamteam.dev`), «окружение агента очищено» (M-4), «агент не может
  одобрить сам себя» (его консоль могла вызвать API от имени пользователя), «CI строго по lock» (образ его не
  использовал).
- **Процесс.** Один PoC роя дважды записал тестовый скилл с фиктивным ключом в настоящую библиотеку скиллов
  пользователя. После предупреждения рой исправил PoC; скилл удалён.

## Выводы

1. Рою за $5 можно доверить первый проход: намеренно встроенный вредный код он находит быстро.
2. Его отчёт нельзя публиковать как есть: половина находок — шум, одна существенная проблема пропущена, а
   итоговое резюме противоречит его же находкам. Независимая проверка обязательна.
3. Самое опасное в DreamTeam — граница между хабом и агентами: всё, что хаб читает или запускает из рабочей
   папки агента (как git-конфиг в F-03), надо считать данными агента.

## Материалы

Отчёт роя, внешняя проверка, PoC и трейсы агентов будут выложены отдельно, когда их очистят от локальных путей.

Нашли уязвимость — сообщите приватно, как описано в [SECURITY.md](../../../SECURITY.md).
