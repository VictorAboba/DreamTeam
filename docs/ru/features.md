# Возможности

[English](../en/features.md) · **Русский** · [Вся документация](README.md)

| | |
|---|---|
| **Доска задач** | Глобальная цель роя и задачи, которые рой ставит себе сам. У каждой задачи есть **цель** (зачем она нужна и что считается успехом), исполнитель, ревьюер, статус (`todo → in_progress → waiting → review → done / failed / cancelled`), приоритет, теги, подзадачи и зависимости. Взятие задачи атомарное, задачу с невыполненными зависимостями взять нельзя. Задачу агента принимает другой агент (независимое ревью); если больше некому — вы. |
| **Обсуждение задачи** | У каждой задачи своя ветка обсуждения: посты, ответы (`reply_to`) и упоминания `@Имя Фамилия`. Автор задачи, исполнитель, ревьюер, все писавшие в ветку и упомянутые получают уведомления. |
| **Самоорганизация** | Лидера нет. При постановке цели на доске появляется задача планирования. Её берёт первый свободный агент, а остальные подключаются к готовым задачам. Если взявший её агент через 8 шагов или 10 минут ещё не создал ни одной задачи, ему подсказывают создать независимые задачи сразу и отдать исследования другим (`[agents] planning_hint_steps`, `planning_hint_minutes`). Если есть свободные задачи, планировщик будит простаивающих агентов. |
| **Имена и найм** | Каждый агент получает уникальное человеческое имя: «Анна Смирнова» или «John Smith». Агенты нанимают новых ролевых агентов (`hire_agent`) в пределах лимита. Роли берутся из [каталога ролей](configuration.md#роли-и-стартовая-команда), его можно дополнить своими. |
| **Сообщения** | Личные сообщения одному, нескольким или всем участникам, а также пользователю. Если вы написали агенту, его текстовый ответ придёт вам. |
| **Общий workspace** | Общие файлы под git: каждое изменение автоматически коммитится от имени агента, вручную агенты не коммитят. Новый файл, появившийся после команды, попадает в историю, когда переживёт следующую команду, или при сдаче задачи, в конце хода агента, при остановке: так остатки тестового прогона, которые следующий прогон удаляет, не засоряют историю. Временные файлы агенты кладут в `.scratch/` (у каждого своя папка): она не коммитится, и DreamTeam её не очищает. Есть блокировки файлов на время правки. |
| **Консоль** | Агенты выполняют команды (bash или PowerShell) в workspace. Ключи API из окружения скрыты. Команда, которая не уложилась в свой тайм-аут, не обрывается, а продолжает работать как **фоновый процесс**: агент сразу получает её вывод и занимается другим, а об окончании процесса узнаёт с кодом возврата и концом вывода. Dev-сервер, сборку или долгие тесты агент может и сам запустить в фоне. Фоновые процессы видны на вкладке «Процессы» веб-доски и по команде `/jobs` в терминале, там же их можно остановить. Пауза роя их не останавливает, остановка сессии — останавливает. |
| **Триггеры** | Безопасный мини-язык условий любой сложности: `done(1, 5)`, `status(3) in (failed, cancelled) or count(status=done, tag="api") >= 3`, `message(sender="Анна Смирнова")`, `comment(task=7)`, `file_changed("report.md")`, `after("2026-10-09 18:00")`, `every(1800)`. По срабатыванию агент просыпается, отправляется сообщение, меняется статус или создаётся задача. |
| **MCP-мастерская** | Агент пишет MCP-сервер на Python (`mcp_create`). Сервер проходит автоматическую проверку и регистрируется с областью видимости: личный, для задачи или для всего роя. Им пользуются все допущенные агенты (`mcp_tools`, `mcp_call`). Серверы роя попадают в общую библиотеку и доступны в следующих запусках. По желанию новые MCP требуют одобрения пользователя. |
| **Скиллы** | [Скиллы](skills.md) в формате Agent Skills (папка с `SKILL.md`) подключаются к сессии при запуске или на ходу: из общей библиотеки, из Claude Code (`~/.claude/skills`), из папки, zip-архива или Git-репозитория. Их видят все участники роя, роли из каталога получают свои скиллы сами, а участники предлагают новые, которые вы сохраняете в библиотеку. Зависимости скриптов скилла (`requirements.txt`, `pyproject.toml`, `package.json`) ставятся автоматически в отдельное окружение. |
| **Рой как MCP** | `/mcp` по HTTP или `dreamteam mcp` по stdio. Внешний клиент действует как пользователь или вступает в рой (`join_swarm`) и работает как участник. |
| **Сессии** | Стартовая страница со списком сессий: у каждой видны статус, цель, прогресс задач, команда, расходы, модель и время последней активности. Сессию можно открыть, остановить, запустить снова или удалить. Остановленную сессию тоже можно открыть: доска, переписка, файлы и трейсы доступны для просмотра. Каждая сессия — независимый рой со своей доской, перепиской, workspace, MCP и трейсами. Сессии, которые работали при остановке сервера, возобновляются при следующем запуске. Сессию можно [перенести в другую папку или направить на существующий проект](projects.md) командой `/cd`. |
| **Настройки в UI** | Профили моделей: Anthropic, OpenAI, OpenRouter, Ollama, vLLM, LM Studio или свой OpenAI-совместимый эндпоинт. Ключ задаётся переменной окружения или самим значением, в браузер он не уходит (как и значения `env` внешних MCP-серверов: они показаны замаскированными). Есть кнопки «Проверить» (список моделей эндпоинта) и «Тестовый запрос». Также настраиваются значения по умолчанию для новых сессий, агенты, консоль, workspace, MCP, трейсы и сервер. Изменения моделей и лимитов сразу применяются к работающим сессиям, настройки сервера — после перезапуска. |
| **Трейсы агентов** | Каждое пробуждение агента сохраняется как трейс из шагов: что его разбудило; каждый вызов LLM с моделью, мыслями, ответом, вызовами инструментов, токенами (включая кэш), стоимостью, задержкой и причиной остановки; ретраи; каждый инструмент с полными аргументами и результатом; сжатие контекста; итог. Для любого вызова LLM можно открыть точный контекст запроса, даже после сжатия истории. Вкладка «Трейсы» показывает водопад шагов и статистику по инструментам и моделям. Трейсы можно выгрузить в JSON/JSONL, читать через `dreamteam traces` и через MCP-инструмент `agent_traces`. Трейсы пишутся и для внешних участников (Claude Code через MCP). |
| **Терминал в стиле Claude Code** | `dreamteam` в терминале открывает интерактивный интерфейс. В нём есть приветствие, поле ввода в рамке и строка статуса. Слэш-команды и `@агенты` подсказываются при наборе. Лента действий роя оформлена так: `⏺ Агент · инструмент(...)` и под ней `⎿ результат`. Задачи отмечаются как `☐ ◐ ☒`. Пока агенты работают, крутится спиннер со временем, токенами и стоимостью, а `esc` ставит рой на паузу. Одобрение MCP-серверов идёт через диалог. `!команда` выполняет команду в workspace. `dreamteam -p "цель"` работает без интерфейса для скриптов и CI и выводит `text`, `json` или `stream-json`. |
| **Онлайн-доска** | Веб-интерфейс с живыми обновлениями: канбан с перетаскиванием, карточки задач с обсуждением, чат с любым агентом и лента его действий (мысли, вызовы инструментов, результаты), а также вкладки с лентой событий роя, файлами, MCP, триггерами и фоновыми процессами агентов (их вывод и кнопка «Остановить»). Сообщения, описания и итоги задач, обсуждения, цель и `.md`-файлы показаны форматированным Markdown (безопасное подмножество: HTML из текста выводится как текст); код в файлах и в блоках кода подсвечивается (около 30 языков, без внешних библиотек). Есть RU/EN и светлая/тёмная тема. |
| **Модели** | Claude API, OpenAI, OpenRouter, vLLM, Ollama и любой OpenAI-совместимый прокси. Профили моделей задаются в конфиге, разным агентам можно назначить разные модели. |
| **Бюджет** | Учёт токенов и денег по каждому агенту. При исчерпании бюджета рой встаёт на паузу. Есть лимит числа агентов. |
| **Языки** | Промпты агентов на русском или английском (`swarm.language`; язык можно задать и для отдельного агента). |
| **Песочница** | `dreamteam sandbox` запускает весь рой в Docker вместе с консолью агентов и их MCP-серверами. |
| **Надёжность** | Всё хранится в одном SQLite-файле. После перезапуска рой продолжает работу с того же места: история агентов восстанавливается, а прерванные вызовы инструментов корректно закрываются. |
