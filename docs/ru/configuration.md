# Конфигурация (`dreamteam.toml`)

[English](../en/configuration.md) · **Русский** · [Вся документация](README.md)

Глобальные настройки лежат в `<home>/dreamteam.toml`. Их удобнее менять на вкладке «Настройки»: страница проверяет
значения перед сохранением и хранит предыдущую версию в `dreamteam.toml.bak`. Ручная правка файла тоже работает,
но комментарии при сохранении из UI не сохраняются; правка файла при работающем сервере подхватывается. При создании
сессии можно переопределить язык, стартовую команду (роли и число агентов), бюджет, профиль модели, число шагов,
одобрение MCP и [уточнение цели](features.md). Эти значения хранятся в `sessions/<id>/session.json`; остальное
берётся из глобальных настроек.
У уже созданной сессии кнопка ⚙ на её странице меняет бюджет и максимум агентов, а также её собственные лимиты
фоновых процессов (на участника, на сессию, предел жизни, потоки вычислений), параметры агентов (шаги за
пробуждение, окно контекста, лимит вывода инструмента, напоминание простаивающим, параллельные вызовы LLM, сколько
триггер `file_changed` ждёт, пока файл перестанет меняться, как часто повторяющийся триггер может будить владельца),
сеть и уточнение цели. Пустое
поле означает значение из общих настроек; изменения применяются сразу, без перезапуска. У сессии `main` (и у доски
`dreamteam run`) ⚙ меняет только бюджет и максимум агентов: остальное задаётся в общих настройках.
Цель задаётся при создании сессии (ключ `goal` в `[swarm]` используется только в режиме `dreamteam run` и в сессии
`main` бывшего проекта).

```toml
[swarm]                  # значения по умолчанию для новых сессий
name = "Мой рой"
language = "ru"          # язык промптов агентов: ru | en
start_agents = 3         # сколько агентов стартует
max_agents = 8           # максимум ИИ-агентов (нанимают новых сами; участники через MCP не считаются)
max_cost_usd = 5.0       # бюджет; при исчерпании — пауза
starting_roles = []      # стартовая команда по порядку: ["architect", "developer", "developer", "tester"]
independent_review = true # задачу агента принимает другой участник (или вы, если больше некому)
network = "on"           # "off" — у команд агентов и их MCP-серверов нет интернета (см. «Сессия без интернета»)
clarify = false          # true — планировщик сначала спрашивает вас о цели; важный вопрос агента ставит рой на паузу

[[roles]]                # своя роль в каталоге (встроенную меняют, указав её id: name = "tester")
name = "Дизайнер"
description = "Ты проектируешь интерфейсы: макеты, тексты экранов, сценарии пользователя."
model = ""               # профиль модели для этой роли ("" — по умолчанию)

[agents]
default_model = "default"
max_steps_per_turn = 40
context_tokens = 120000  # порог сжатия истории агента в резюме
file_settle_seconds = 60 # file_changed срабатывает, когда файл столько секунд не меняется или менявшие его агенты закончили ход (0 — при каждом изменении)
file_max_wait_seconds = 300 # ...но не позже, чем через столько секунд после первого изменения (0 — без предела)
trigger_wake_seconds = 180  # повторяющийся триггер участника будит его не чаще раза в столько секунд; срабатывания между пробуждениями приходят одним уведомлением (0 — будить при каждом)

[shell]                  # консоль агентов (полный список — на вкладке «Настройки»)
timeout = 120            # столько секунд вызов ждёт команду; дальше она работает как фоновый процесс
foreground_max = 180     # ИИ-агент ждёт команду не дольше этого, какой бы тайм-аут он ни задал
max_jobs = 16            # фоновых процессов в сессии (0 — без фоновых процессов)
job_max_minutes = 480    # сколько живёт процесс, запущенный в фоне намеренно или оставленный командой (0 — без предела)

[workspace]
git = true               # общий workspace под git с автокоммитами
lock_ttl_minutes = 30    # на сколько минут блокируется файл, если агент не указал срок (не меньше 1)
lock_wanted_minutes = 5  # напомнить держателю файла, который ждут, когда он держит его столько минут (0 — сразу)

[models.default]         # Claude
provider = "anthropic"
model = "claude-opus-5-5"
api_key_env = "ANTHROPIC_API_KEY"
effort = "medium"
fallbacks = "default"           # серверный fallback при отказе модели (beta)
thinking_mismatch = "drop_block" # не падать при изменении префикса диалога (beta)
max_tokens = 16000
max_tokens_ceiling = 32000      # после ответа, обрезанного по лимиту, лимит удваивается до этого (по умолчанию 2 × max_tokens)

[models.local]           # Ollama / vLLM / OpenRouter — любой OpenAI-совместимый API
provider = "openai"
base_url = "http://localhost:11434/v1"
model = "qwen3:32b"
api_key = "ollama"
input_price = 0
output_price = 0

[mcp]
require_approval = false
library_dir = "~/.dreamteam/library"  # общая библиотека MCP-серверов (DREAMTEAM_MCP_LIBRARY_DIR имеет приоритет)
[mcp.external.fetch]     # внешние MCP-серверы для роя
command = ["uvx", "mcp-server-fetch"]
description = "Загрузка веб-страниц"

[tracing]
enabled = true           # трейсы агентов
max_payload_chars = 200000
retention_days = 0       # 0 — хранить всегда

[server]
host = "127.0.0.1"
port = 8765
resume_sessions = true   # возобновлять сессии, которые работали при остановке
```

Для цен известных моделей Claude используются встроенные значения. Для остальных моделей укажите
`input_price` и `output_price` в долларах за 1M токенов; `0` означает бесплатную модель (например, локальную), а пустое
поле — «не указано». Если провайдер сам сообщает стоимость запроса, берётся она. У профиля без цен, чей провайдер не
сообщает стоимость, токены считаются по $0: показанные расходы ниже настоящих, и бюджет сессии таких вызовов не видит.
DreamTeam об этом предупреждает:

- в настройках карточка профиля показывает предупреждение с кнопками «Указать цены» и «Бесплатная модель (0 / 0)»,
  а результат «Тестового запроса» говорит, как получена его стоимость;
- после первого такого вызова с момента запуска сессии приходит уведомление с профилем, моделью и недостающими
  ценами (в `dreamteam -p` — ещё и в stderr);
- `dreamteam serve` и `dreamteam run` печатают замечание после сообщения о запуске, а `/model` в терминале показывает
  столбец «Цены».

Агент работает на профиле модели, с которым его наняли. Если переименовать этот профиль на вкладке «Настройки», агент
останется на нём под новым именем — и в работающих, и в остановленных сессиях. Агент, чей профиль удалён (или
переименован вручную в `dreamteam.toml`), работает на профиле по умолчанию.

## Роли и стартовая команда

В DreamTeam есть каталог ролей: универсал, разработчик, тестировщик, ревьюер, аналитик, архитектор, технический
писатель и исследователь. У каждой роли есть описание, которое попадает в системный промпт агента при найме, а
также свои инструкции и профиль модели, если они заданы. Каталог настраивается на вкладке «Настройки» → «Роли»
(или в `[[roles]]`). Там можно поправить встроенную роль, скрыть её или добавить свою. Правка доходит только до
агентов, нанятых после неё: промпты уже работающих агентов не меняются. Агенты нанимают по каталогу
(`hire_agent` с ролью из него может обойтись без инструкций), а вы — командой `/hire Роль` или кнопкой найма на
доске. **Стартовая команда** — это роли агентов, с которыми начинается сессия. Её задают так:

- в окне новой сессии или в настройках («Роль ×N», строки по порядку);
- флагом `--team "architect, developer*2, tester"`;
- командой `/team` в терминале.

Агенты сверх списка становятся универсалами.

## Общие папки и настройки этого компьютера

Некоторые папки общие для всех сессий и лежат вне домашней папки, в `~/.dreamteam`: библиотека скиллов
(`[skills] library_dir`, по умолчанию `~/.dreamteam/skills`), окружения зависимостей скиллов (`[skills] envs_dir`,
`~/.dreamteam/skill-envs`) и библиотека MCP-серверов (`[mcp] library_dir`, `~/.dreamteam/library`). Переменные
окружения `DREAMTEAM_SKILLS_DIR`, `DREAMTEAM_SKILL_ENVS_DIR` и `DREAMTEAM_MCP_LIBRARY_DIR` имеют приоритет над
этими настройками: так песочница Docker задаёт свои папки скиллов, а тесты — все три. В консоль агентов эти
переменные не попадают.

[Импорт](transfer.md) (`dreamteam import`) никогда не меняет настройки, которые относятся к самому компьютеру, —
ни в общих настройках, ни в настройках сессий: `server.host`, `server.port`, `shell.program`, `skills.library_dir`,
`skills.envs_dir`, `skills.python` и `mcp.library_dir` сохраняют здешнее значение, а ключи API и значения `env`
внешних MCP-серверов в экспорт вообще не попадают.
