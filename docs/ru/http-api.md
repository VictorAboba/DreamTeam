# HTTP API

[English](../en/http-api.md) · **Русский** · [Вся документация](README.md)

HTTP API позволяет программе пользоваться роем как сервисом. Сервер сайта загружает документ (или называет папку,
которую разрешил владелец), запускает сессию с целью, показывает её ход, отвечает агентам, если они спрашивают, и
получает результат в JSON и файлах. Это HTTP-форма `dreamteam -p` ([Терминальный интерфейс](terminal.md)): всё
описано через сессию, её цель, события, запросы к пользователю, результат и файлы.

API живёт под `/api/v1` на любом хабе домашней папки: `dreamteam serve`, собственный хаб TUI, `dreamteam mcp` в
домашней папке и `dreamteam sandbox` домашней папки. У `dreamteam run` и у песочницы отдельного проекта его нет.
Собственные маршруты доски (`/api/...`, WebSocket, `/mcp`) в него не входят и могут меняться в любом выпуске;
`/api/v1` меняется только так, как сказано в разделе [Совместимость](#совместимость). Полный контракт — раздел 21
[спецификации модулей](../SPEC.md) (на английском).

## Как включить

У API свой токен, отдельный от токена хаба: `DREAMTEAM_API_TOKEN` в окружении команды, которая запускает хаб. Клиент
отправляет его в заголовке `Authorization: Bearer <токен>`.

```bash
export DREAMTEAM_API_TOKEN=$(python3 -c "import secrets; print(secrets.token_urlsafe(32))")
export DREAMTEAM_HUB_TOKEN=$(python3 -c "import secrets; print(secrets.token_urlsafe(32))")   # рекомендуется, см. ниже
dreamteam serve --no-browser
```

Тогда `serve` печатает адрес API вместе с остальными:

```
DreamTeam is running.
  Sessions: http://127.0.0.1:8765/
  MCP:      http://127.0.0.1:8765/mcp
  API:      http://127.0.0.1:8765/api/v1
  Home:     /home/you/DreamTeam
```

`dreamteam status` тоже печатает `API: <хаб>/api/v1`, пока такой хаб работает; сам токен не печатает ни та, ни другая
команда.

- Вместо токена хаб может получить его SHA-256 (64 шестнадцатеричные цифры) в `DREAMTEAM_API_TOKEN_SHA256`, как и для
  токена хаба. Значение, которое не является SHA-256, отклоняется с предупреждением в логе, и тогда ему не подходит ни
  один токен API (токен хаба по-прежнему работает, как владелец).
- Токен хаба (и собственные клиенты хаба) тоже работает на `/api/v1`, как владелец: он видит все сессии. Токен API
  видит только сессии, созданные через API ([Безопасность](#безопасность)). Хаб с токеном хаба и без токена API
  обслуживает API только для владельца.
- Хаб без обоих токенов отвечает на любой запрос к `/api/v1` 403 `api_disabled`, на `127.0.0.1` тоже.
- Хаб, у которого токен API совпадает с токеном хаба, не запускается: тот, у кого токен API, открыл бы все маршруты
  хаба.
- Хаб с токеном API и без токена хаба запускается с предупреждением в логе (и в выводе `serve`): доска, настройки и
  `/mcp` по-прежнему отвечают всякому, кто дошёл до порта, без токена, так что ошибка сайта на том же компьютере могла
  бы до них добраться. Задайте и `DREAMTEAM_HUB_TOKEN` или запускайте хаб в
  [песочнице](sandbox.md#http-api-в-песочнице). В образе Docker такого предупреждения нет: хаб там слушает `0.0.0.0`,
  и токен хаба ему нужен в любом случае.
- DreamTeam при старте убирает обе переменные из своего окружения: они не попадают ни в команды агентов, ни в
  MCP-серверы, ни в git самого DreamTeam, что бы ни говорил `[shell] pass_env`.

В [песочнице Docker](sandbox.md#http-api-в-песочнице) задайте `DREAMTEAM_API_TOKEN` на хосте перед
`dreamteam sandbox ~/DreamTeam`: контейнер получает только его SHA-256, а при старте печатается
`API:      http://127.0.0.1:8765/api/v1  (header Authorization: Bearer <your DREAMTEAM_API_TOKEN>)`.

Лимиты API — в разделе `[api]` файла `dreamteam.toml`, он правится только вручную
([Настройки HTTP API](configuration.md#настройки-http-api)); изменение действует со следующего запроса.

## Быстрый старт с curl

```bash
API=http://127.0.0.1:8765/api/v1
AUTH="Authorization: Bearer $DREAMTEAM_API_TOKEN"
JSON="Content-Type: application/json"

# что клиент может выбрать: языки, команды, роли, модели, скиллы, папки, лимиты
curl -s -H "$AUTH" $API/options

# 1. загрузить файл (тело запроса как есть); "upload" в ответе — его токен на час
curl -s -H "$AUTH" -H "Content-Type: application/octet-stream" --data-binary @report.pdf \
     "$API/uploads?filename=report.pdf"
# {"upload": "q1mH...", "filename": "report.pdf", "bytes": 48213, "unpack": false, "expires_in": 3600}

# 2. запустить сессию с этим файлом
curl -s -H "$AUTH" -H "$JSON" $API/sessions -d '{
  "goal": "Кратко изложи отчёт\nОдна страница, простыми словами, в summary.md",
  "files": ["q1mH..."], "language": "ru", "max_cost_usd": 2, "answers": "manual",
  "client_ref": "job-42"}'
# 202 {"session": {"id": "5f0c...", "name": "007-kratko-izlozhi-otchet", "state": "starting", ...}}

# 3. следить за событиями: длинные опросы с последнего id, пока "final" не станет true, а "more" — false
curl -s -H "$AUTH" "$API/sessions/5f0c.../events?after=0&wait=30"
# {"events": [{"id": 41, "type": "task.updated", "text": "◐ #3 Изложить отчёт — Анна", ...}],
#  "last": 41, "more": false, "state": "running", "final": false}

# 4. что ждёт пользователя ("answers": "manual" оставляет ответы клиенту), и ответ
curl -s -H "$AUTH" $API/sessions/5f0c.../requests
curl -s -H "$AUTH" -H "$JSON" $API/sessions/5f0c.../requests/q12 -d '{"text": "Таблицы оставь"}'

# 5. результат, файлы, zip с ними
curl -s -H "$AUTH" $API/sessions/5f0c.../result
curl -s -H "$AUTH" $API/sessions/5f0c.../files
curl -s -H "$AUTH" -o summary.md $API/sessions/5f0c.../files/summary.md
curl -s -H "$AUTH" -o result.zip $API/sessions/5f0c.../archive

# 6. следующее указание той же сессии, потом удалить её
curl -s -H "$AUTH" -H "$JSON" $API/sessions/5f0c.../continue -d '{"text": "Добавь список открытых вопросов"}'
curl -s -H "$AUTH" -X DELETE "$API/sessions/5f0c...?confirm=5f0c..."
```

В PowerShell вызывайте `curl.exe` (не псевдоним `curl`), а тело JSON кладите в файл: `-d "@body.json"`.

Тот же цикл на Python, только стандартная библиотека:

```python
import json, os, urllib.request

API = "http://127.0.0.1:8765/api/v1"
AUTH = {"Authorization": "Bearer " + os.environ["DREAMTEAM_API_TOKEN"]}

def call(method, path, body=None):
    headers = dict(AUTH, **({"Content-Type": "application/json"} if body is not None else {}))
    data = None if body is None else json.dumps(body).encode()
    request = urllib.request.Request(API + path, data=data, method=method, headers=headers)
    with urllib.request.urlopen(request, timeout=90) as answer:
        return json.load(answer)

session = call("POST", "/sessions", {"goal": "Напиши хайку о море", "client_ref": "haiku-1"})["session"]
after = 0
while True:
    page = call("GET", f"/sessions/{session['id']}/events?after={after}&wait=30")
    for event in page["events"]:
        if event["text"]:
            print(event["text"])
    after = page["last"]
    if page["final"] and not page["more"]:
        break
result = call("GET", f"/sessions/{session['id']}/result")
print(result["status"], result["summary"])
```

## Формат

- Тела запросов и ответы — JSON, кроме загрузок (файл как есть) и скачивания (байты файла). Время — секунды Unix,
  деньги — доллары США.
- Каждый POST и PATCH отправляет `Content-Type: application/json` (charset допустим), в том числе `stop` без тела;
  иначе — 415 `unsupported_media_type`. Загрузки вместо этого принимают `application/octet-stream` или
  `application/zip` и никогда не JSON. Тело — не больше 1 МиБ (413 `too_large`), пустое тело считается `{}`, а тело,
  которое не является объектом JSON или содержит `NaN`, `Infinity` либо число, слишком большое для float, — 400
  `bad_request`. Поле со значением `null` считается не заданным.
- Поле, которого сервер не знает, в теле или в строке запроса — 400 `unknown_field`, так что опечатка не проходит
  молча. Поле строки запроса, заданное дважды, — 400 `bad_request`.
- Ошибки — `{"error": текст, "code": код}`, отказы защиты хаба тоже; у некоторых кодов есть свои дополнительные поля.
  Текст — на английском и для людей, его формулировка может меняться: программы смотрят на `code` ([Ошибки](#ошибки)).
- На `/api/v1` учитывается только заголовок `Authorization`: cookie доски и `?token=` там ничего не дают.

## Маршруты

| метод и путь | ответ |
|---|---|
| GET `/api/v1/options` | что клиент может выбрать (ниже) |
| POST `/api/v1/uploads?filename=<имя>[&unpack=true]` | 201 `{"upload", "filename", "bytes", "unpack", "expires_in": 3600}` ([Загрузки](#загрузки)) |
| POST `/api/v1/sessions` | 202 `{"session": сводка}`; 200 с уже созданной сессией при повторе `client_ref` ([Создание сессии](#создание-сессии)) |
| GET `/api/v1/sessions?state=&limit=` | `{"sessions": [сводка]}`, сначала новые; `limit` 1–200, по умолчанию 50; `state` оставляет одно [состояние](#состояния) |
| GET `/api/v1/sessions/{id}` | `{"session": сводка}` |
| PATCH `/api/v1/sessions/{id}` | `{"max_cost_usd"?, "max_agents"?, "wrap_up"?}` → `{"session"}` ([Лимиты](#лимиты-остановка-и-удаление)) |
| POST `/api/v1/sessions/{id}/continue` | `{"text"}` → `{"session"}` ([Следующее указание](#следующее-указание-continue)) |
| POST `/api/v1/sessions/{id}/stop` | `{"session"}`; фоновые процессы агентов останавливаются вместе с ней |
| DELETE `/api/v1/sessions/{id}?confirm={id}` | `{"ok": true}`, плюс `"folder_kept": {"root", "path"}` для папки, в которой сессия работала на месте |
| GET `/api/v1/sessions/{id}/events?after=&wait=&limit=&detail=&lang=` | `{"events", "last", "more", "state", "final"}` ([События](#события)) |
| GET `/api/v1/sessions/{id}/events/stream?after=&detail=&lang=` | Server-Sent Events |
| GET `/api/v1/sessions/{id}/requests` | `{"requests": [запрос]}`, сначала старые ([Запросы](#запросы-и-сообщения)) |
| POST `/api/v1/sessions/{id}/requests/{rid}` | ответ → `{"ok": true, "session"}` |
| GET `/api/v1/sessions/{id}/messages?after=&limit=` | `{"messages": [...], "last"}`: переписка пользователя с участниками, сначала старые |
| POST `/api/v1/sessions/{id}/messages` | `{"to", "text", "reply_to"?}` → 201 `{"message"}` |
| GET `/api/v1/sessions/{id}/result` | [результат](#результат), и пока сессия работает (`"final": false`) |
| GET `/api/v1/sessions/{id}/files?path=&scratch=` | `{"path", "entries": [...]}`: одна папка файлов сессии ([Файлы](#файлы)) |
| GET `/api/v1/sessions/{id}/files/{path}?scratch=` | байты файла |
| GET `/api/v1/sessions/{id}/archive?path=&scratch=` | zip папки сессии или одной папки внутри неё |

`{id}` — это `id` сессии из её сводки: 32 шестнадцатеричные цифры, никогда не используется повторно. `name` в сводке —
имя папки, которое показывает доска (`/s/<name>/`); номера папок после удаления возвращаются, поэтому клиент всегда
хранит `id`.

`GET /api/v1/options` отвечает `{"api": 1, "version", "languages", "language", "teams": [{name, roles}], "roles":
[{key, name, description}], "models": [{name, provider, model}], "default_model", "skills": [{name, description}],
"folders": [{name, in_place}], "limits": {...}}`. В нём никогда нет ключа, адреса, имени переменной или пути. `limits`:
`upload_max_mb` (одна загрузка и всё, что копирует одно создание), `upload_max_files` (файлы, которые копирует одно
создание), `files_per_session` (20), `uploads_pending`, `max_running` и `archive_max_mb`.

## Загрузки

`POST /api/v1/uploads?filename=<имя>` сохраняет тело как один файл (любой: PDF, CSV, zip) и отвечает его токеном.
Токен передаётся в `files` при создании сессии, и файл с этим именем попадает в папку сессии до первого запуска.

- `unpack=true` принимает zip и распаковывает его в папку сессии, по правилам
  [копии файлов](projects.md#работа-с-копией-файлов): zip одной папки даёт её содержимое; `.git`, `node_modules`,
  `.venv`, `venv`, `__pycache__`, ссылки и, на верхнем уровне, собственные имена сессии (`.scratch`, `.gitignore`,
  `.dreamteam`, `mcp`) пропускаются. Без него zip — такой же файл, как любой другой.
- Имя отклоняется (400 `bad_name`), а не исправляется, если оно пустое, `.` или `..`; содержит `/`, `\`, `:`, NUL или
  другой непечатаемый символ (управляющие, переключатели направления текста, символы нулевой ширины, символы для
  частного использования, разделители строк и абзацев); длиннее 200 символов, 255 байт UTF-8 или 255 единиц UTF-16;
  не может существовать в Windows, на любой ОС (`< > " | ? *`, `CON`, `aux.txt`, точка или пробел в конце); имеет вид
  короткого имени Windows (`GIT~1`); или совпадает, в любом регистре, с `.git`, `node_modules`, `.venv`, `venv`,
  `__pycache__`, `.scratch`, `.gitignore`, `.dreamteam` или `mcp`.
- `[workspace] copy_max_mb` ограничивает одну загрузку (413 `too_large`) и сумму, которую копирует одно создание;
  `copy_max_files` — число файлов, которые копирует одно создание (распакованный zip считает свои файлы). Одновременно
  ждут не больше `[api] uploads_pending` (32) загрузок: ещё одна — 429 `too_many_uploads`.
- Токен живёт час и используется одним успешным созданием. Отклонённое создание (любой 4xx) оставляет все названные
  в нём токены годными для следующей попытки, как и создание, которое не удалось на стороне хаба или было отменено.
- Загрузки API — свои: токен никогда не подходит для диалога «Новая сессия» на доске, и наоборот, а токен, загруженный
  с токеном API, неизвестен владельцу с токеном хаба (404), и наоборот.

## Создание сессии

`POST /api/v1/sessions`:

```json
{"goal": "текст, обязателен: первая строка — заголовок, остальное — описание",
 "title": "одна строка вместо первой строки цели",
 "description": "ещё описание, после собственного описания цели",
 "language": "ru | en",
 "team": "имя сохранённой команды | [\"роль\", ...]",
 "model": "имя профиля",
 "start_agents": 3, "max_agents": 8, "max_cost_usd": 5.0,
 "network": "on | off",
 "files": ["токен загрузки", "..."],
 "folder": {"root": "jobs", "path": "acme/site", "mode": "copy | in_place"},
 "skills": ["имя скилла из библиотеки", "..."],
 "answers": "auto | manual",
 "clarify": false,
 "stop_when_done": true,
 "client_ref": "ваш собственный id этого задания"}
```

Обязательна только `goal`; всё, что не задано, берётся из настроек, как для доски. Ответ — 202 со сводкой в состоянии
`starting`: сессия запускается в фоне, а запуск, который не удался, виден как состояние `failed` с её `error`.

- **Цель и заголовок.** В `goal` должно быть что-то кроме пробелов. Без `title` первая строка цели — заголовок, а
  остальное — описание. С `title` (одна строка, не больше 200 символов) заголовок — `title`, а весь текст цели
  становится описанием, если только первая строка цели и так не совпадает с `title`. `description` добавляется после
  пустой строки. В заголовке не должно быть управляющих символов (табуляции, escape-последовательности) и невидимых
  символов форматирования вроде переключателя направления текста (400 `bad_request`): он как есть попадает в терминал
  и на страницы владельца. Имя папки сессии строится из заголовка.
- **Команда, модель, лимиты.** `team` — имя команды, сохранённой в настройках (400 `unknown_team`, в тексте —
  список имён), или список ролей по порядку (400 `unknown_role` для роли, которой нет в каталоге). Список задаёт
  `start_agents`, если оно не задано; сохранённая команда задаёт его по своему размеру, поэтому `team`-имя вместе с
  `start_agents` — 400. `model` — имя профиля (400 `unknown_model`). `start_agents` и `max_agents` — целые числа не
  меньше 1, и `start_agents` не больше `max_agents`, даже если его задаёт команда; `max_cost_usd` — не меньше 0.
  Провайдер, ключ или адрес никогда не берутся из запроса: это настройки компьютера хаба.
- **`files`**: не больше 20 токенов загрузок, без повторов ([Загрузки](#загрузки)). Два файла с одним именем — 409
  `file_conflict`.
- **`folder`**: папка на компьютере хаба, названная через корень, который указал владелец
  ([Папки](#папки-на-компьютере-хаба)). Другого способа назвать путь на компьютере хаба нет.
- **`skills`**: имена скиллов из библиотеки хаба (их перечисляет `GET options`; в песочнице — и из библиотеки хоста;
  400 `unknown_skill` для другого имени), не больше `[skills] max_attached` (400 `bad_request`). Ни один скилл не
  берётся из пути, Git-адреса или Claude Code.
- **`answers`**: кто отвечает на то, о чём агенты спрашивают пользователя. `auto` (по умолчанию): сам хаб, как это
  делает `dreamteam -p` ([Автоматические ответы](#автоматические-ответы)). `manual`: клиент, через
  [запросы](#запросы-и-сообщения), или владелец на доске. `clarify: true` (планировщик сначала спрашивает,
  [режим уточнения](features.md)) требует `manual`.
- **`stop_when_done`** (по умолчанию true): когда цель достигнута или бюджет поставил сессию на паузу, сессия
  останавливается (вместе с фоновыми процессами), с причиной `done` или `budget` в её событии `session.stopped`.
  `continue` запускает её снова. С false она продолжает работать, как сессия доски.
- **`client_ref`** (не больше 128 печатных символов): повтор после тайм-аута никогда не создаёт второго задания.
  Создание с тем же `client_ref` и тем же телом, что у сессии, которая у API ещё есть, отвечает 200 с этой сессией и
  ничего не создаёт; ещё создающуюся сессию оно дожидается. Тот же `client_ref` с другим телом — 409 `conflict`.
- **`[api] max_running`** (по умолчанию 3, 0 — без ограничения) считает работающие и запускающиеся сессии, созданные
  через API: создание или `continue` сверх него — 429 `too_many_sessions`. Запуски самого владельца (доска,
  терминал, MCP) и возобновление при старте хаба никогда не отклоняются, но учитываются.

Проверки идут до того, как что-либо скопировано или занято, поэтому отклонённое создание ничего не стоит: тело,
`client_ref`, настройки, скиллы, папка, токены загрузок, затем `max_running`.

Сессия, созданная через API, видна на странице сессий со значком «API», в `dreamteam sessions` и `dreamteam status`
с `| HTTP API`, а в списке сессий терминала — с «HTTP API». `dreamteam -c` её никогда не выбирает
([Терминальный интерфейс](terminal.md)): владелец открывает её через `dreamteam -r <name>` (`name` из сводки,
а не её `id`).

## Состояния

`state` в сводке — первое, что выполняется:

| состояние | когда |
|---|---|
| `starting` | её запускает создание или `continue`, или хаб вот-вот возобновит её при своём старте |
| `failed` | её последний запуск не удался (`error` в сводке говорит почему) |
| `created` | она ни разу не запускалась |
| `done` | цель достигнута |
| `budget` | бюджет поставил её на паузу, или эта пауза её остановила |
| `waiting` | она работает, и ответа ждёт запрос, который блокирует работу |
| `paused` | она работает, поставлена на паузу пользователем |
| `running` | она работает |
| `stopped` | остановлена иначе (пользователем, остановкой хаба) |

`final` равно true, когда сессия остановлена и сама не вернётся: она не работает, не запускается, не ждёт
возобновления, и никакая остановка или запуск не идут. С `stop_when_done` конец задания — `done` или `budget` с
`final: true`. Сессия, созданная более ранней версией DreamTeam, — `stopped`, final, с `"earlier_version": true`;
любой маршрут, которому пришлось бы её открыть, отвечает 409 `earlier_version`.

Сводка: `{"id", "name", "title", "state", "final", "error", "goal": {title, description, status, summary} | null,
"language", "model", "cost_usd", "max_cost_usd", "max_agents", "created_at", "started_at", "finished_at", "agents",
"tasks": {статус: n}, "requests", "answers", "stop_when_done", "client_ref", "via", "folder", "board_url",
"earlier_version"}`. Абсолютных путей в ней никогда нет. `board_url` — доска сессии, она указывается, только когда хаб
знает свой публичный адрес (`DREAMTEAM_PUBLIC_URL` или хаб на `127.0.0.1`), иначе null; чтобы её открыть, нужен токен
хаба, а не токен API.

## События

Событие — строка журнала сессии с её id и строкой для людей:

```json
{"id": 41, "type": "task.updated", "ts": 1794463609.8, "actor": "Анна Смирнова", "data": {...},
 "text": "◐ #3 Разобрать документ — Анна"}
```

- `data` — собственные данные события ([типы событий](../SPEC.md), раздел 9), в них могут появляться новые поля.
  Число, которое не является конечным, читается как `null`.
- `text` — строка, которую показывает подробная лента терминала, без цветов, на языке сессии, если `lang=ru` или
  `lang=en` не называет другой. Он равен null только для событий, которых не показывает ни одна лента (`agent.usage`,
  `agent.compacted`). Собственные тексты DreamTeam в нём не называют абсолютных путей; то, что написали агенты
  (сообщения, вызовы инструментов и их результаты), приводится как написано. Формулировки могут меняться от выпуска к
  выпуску.
- `detail=timeline` (по умолчанию) даёт события, которые показывает лента хода работы: задачи, комментарии,
  сообщения, уведомления пользователю, цель, найм, паузы, запуск и конец сессии (`session.started`, `session.stopped`
  с `reason`: `done`, `budget`, `user`, `failed`, `shutdown`, `restart`), фоновые процессы, MCP-серверы, скиллы и
  изменения файлов. `detail=all` даёт все события журнала, включая действия агентов (вызовы инструментов, мысли) и
  расход токенов.

**Опрос.** `GET .../events?after=<последний id>` отвечает событиями после этого id, сначала старые, не больше `limit`
(1–500, по умолчанию 200), с `last` (id, после которого спрашивать в следующий раз), `more` (ещё события уже есть) и
состоянием сессии `state` и `final`. Начните с `after=0` и спрашивайте снова с `after=last`, пока `final` не станет
true, а `more` — false: тогда больше ничего не придёт, если сессию не запустят снова. Страница может быть без событий
при `more` = true (лента пропустила то, что прочитала): спросите снова сразу. `wait` (0–60 секунд, только цифры,
`2.5` можно) держит запрос, которому пока нечего ответить, пока не придёт событие, не изменится состояние или не
выйдет время.

**Поток.** `GET .../events/stream` отправляет те же события как Server-Sent Events: `id: <id>`, `event: <тип>`,
`data: <JSON события>`. Он начинается после `after` или после заголовка `Last-Event-ID`, который важнее (`EventSource`
отправляет его при переподключении). Комментарий `: ping` приходит после 15 секунд без строк. Когда сессия final и все
события отправлены, поток заканчивает одно `event: result` с [результатом](#результат). Удаление заканчивает его без
результата, как и остановка хаба: переподключитесь с `Last-Event-ID`.

Журнал, который сейчас нельзя прочитать (файл остановленной сессии держит другая программа, отключился сетевой
диск), — это 500 `internal` с текстом «The session's journal cannot be read now (the hub's log says why): ask again
later.»; это никогда не пустая страница, которую можно принять за конец. Спросите позже; поток заканчивается без
результата.

## Запросы и сообщения

Запрос — это то, что может дать только пользователь. Его id называет ровно то, о чём спросили, поэтому повторённый
ответ никогда не попадёт в более новый запрос:

```json
{"id": "q12", "kind": "question", "ts", "from": "Анна Смирнова", "text", "pauses_swarm": true}
{"id": "m15", "kind": "message",  "ts", "from": "Анна Смирнова", "text"}
{"id": "r7-418", "kind": "review", "ts", "from": "Анна Смирнова", "task": {"id", "title", "result"}}
{"id": "s-web-3f9a0c1b2d4e", "kind": "mcp", "ts", "from": "Анна Смирнова", "server": {"name", "description", "tools"}}
```

- `question`: вопрос, который ставит рой на паузу ([режим уточнения](features.md)), или вопросы планировщика, который
  ждёт ответов пользователя, прежде чем планировать. Ответ `{"text"}`; он заканчивает паузу.
- `message`: последнее сообщение участника пользователю, на которое пользователь ещё не ответил, по одному на
  участника. Работу оно не блокирует: сюда попадают и отчёты.
- `review`: задача, которая ждёт ревью пользователя. Новая сдача — новый id. Ответ `{"approve": true|false,
  "comment"?}`; комментарий — не больше 20 000 символов.
- `mcp`: MCP-сервер, который написал агент, ждёт одобрения (`[mcp] require_approval`). Ответ `{"approve":
  true|false}`; у сервера, который агент пересобрал после получения списка, новый id, а старый даёт 404.

Запросы `question`, `review` и `mcp` блокируют работу: состояние тогда — `waiting`. `GET .../requests` перечисляет то,
что ждёт сейчас, сначала старое; `requests` в сводке их считает. Сессия, которая не работает, перечисляет только то,
что блокирует её работу: на `message` можно ответить, только пока сессия работает, поэтому задание, которое
остановилось с неотвеченным последним отчётом участника, не перечисляет ничего (отчёт остаётся в
`GET .../messages`) и перечислит его снова, если снова заработает.

`POST .../requests/{rid}` отвечает на один из них от имени пользователя и возвращает `{"ok": true, "session"}`. Поле
из ответа на запрос другого вида — 400 `unknown_field`, отсутствующее поле или поле не того типа — 400 `bad_request`.
Запрос, на который тем временем ответили или который заменили, — 404 `not_found` (запросите список снова). Сессия
должна работать: остановленная — 409 `not_running` (`continue` запускает её с текстом; выполненная цель с ним
открывается снова, и агенты снова работают и тратят бюджет). Второй ответ тому же
MCP-серверу, пока первый ещё проверяется, — 409 `conflict`; как и всё, от чего отказывается рой, с его текстом (путь
на компьютере хаба в нём переписан, как в любой ошибке, см. [Ошибки](#ошибки)). У
текста (ответа на вопрос или сообщение, сообщения, `continue`) отбрасываются пробелы по краям, после этого в нём
должно что-то остаться, не больше 50 000 символов и без одиночных суррогатов (одинокий `\ud800` в JSON). Прочитанным
на доске отмечается только сообщение, которое называл запрос: более ранние сообщения, которых ни один запрос не
перечислял, остаются там непрочитанными.

**Сообщения.** `GET .../messages?after=&limit=` читает переписку пользователя с участниками, сначала старые: то, что
отправил пользователь, и то, что дошло до пользователя (`{id, ts, from, to, text, reply_to}`; `limit` 1–500, по
умолчанию 200; `last` — самый новый выданный id, иначе `after`). `POST .../messages` отправляет сообщение от имени
пользователя: `{"to": ["all"] или от 1 до 100 имён участников, "text", "reply_to"?: id сообщения}` → 201
`{"message"}`. То, от чего отказывается почта роя (неизвестный или ушедший участник), — 400 `bad_request`;
остановленная сессия — 409 `not_running`. Остановленная сессия, базу которой нельзя прочитать (повреждённый файл), не
отдаёт ни запросов, ни сообщений.

### Автоматические ответы

При `"answers": "auto"` хаб отвечает за пользователя, как это делает `dreamteam -p`, при каждом запуске сессии, откуда
бы её ни запустили:

- каждое сообщение участника пользователю получает «Пользователь недоступен (неинтерактивный режим): прими решение сам
  и продолжай работу.» (на языке сессии), не больше 50 за запуск;
- задача, которая ждёт ревью пользователя, принимается с пометкой, что её никто не проверял, один раз на сдачу;
- на вопрос, который ставит рой на паузу, даётся ответ; планировщик уточняющей сессии планирует, не спрашивая.

После 50 ответов сообщения больше не получают ответа: они ждут как запросы `message`, и сессия один раз за запуск
сообщает об этом пользователю (уведомлением). Ревью и паузы с вопросом по-прежнему получают ответ. MCP-серверы
автоматически никогда не одобряются: с `[mcp] require_approval = true` сессия `auto` может оставаться в `waiting`,
пока не ответит клиент или владелец. `dreamteam -p -r <name>` на такой сессии не шлёт ничего от себя, так что дважды ни
на что не отвечают.

## Следующее указание (`continue`)

`POST .../continue {"text"}` делает с текстом то же, что `dreamteam -p -r <name> "<текст>"` со своим запросом: без цели
текст становится целью; достигнутая цель возвращается в работу с этим текстом; ожидающий вопрос получает его как
ответ; иначе это сообщение координатору (участнику, который держит задачу планирования, иначе первому агенту). Сессия,
которую пользователь поставил на паузу, тоже продолжается.

- В работающую сессию текст передаётся сразу. 409 `budget_exhausted`, пока бюджет исчерпан (сначала поднимите его
  через PATCH), 409 `conflict` для того, от чего отказывается рой.
- Остановленная, неудачно запущенная или запускающаяся сессия отвечает 200 с состоянием `starting`: она запускается
  в фоне, и текст передаётся сразу после запуска. Сначала проверяются `max_running` и бюджет (429, 409). Несколько
  `continue` передаются в том порядке, в каком пришли. `continue`, отправленный после остановки, снова запускает
  сессию со своим текстом; отправленный, пока запуск не удаётся, пробует запуск ещё раз.
- Текст, который после такого запуска передать не удалось, виден в `error` сводки, из `api.error` сессии
  `{code, text}`: `budget_exhausted`, `conflict`, код другого отказа, `internal` или `not_running`, когда остановка или
  удаление, отправленные после `continue`, пришли раньше («send the text again»). Следующий переданный текст это
  очищает. Неудачный запуск вместо этого показывает свою ошибку.

## Лимиты, остановка и удаление

- `PATCH /api/v1/sessions/{id}` с `max_cost_usd`, `max_agents` или `wrap_up` меняет их, как ⚙ на доске, и для
  остановленной сессии тоже. Бюджет, который покрывает потраченное, снимает паузу по бюджету. `wrap_up: true` просит
  команду закончить с тем, что есть (409 `conflict` для сессии, которая ни разу не запускалась). Значение, которое не
  может быть лимитом (`max_agents` меньше 1 или больше 64 бит, отрицательный бюджет, число, слишком большое для
  float), — это 400 `bad_request`, и ничего не меняется. PATCH сам проверяет свой `Content-Type` (415).
- `POST .../stop` останавливает сессию и её фоновые процессы (причина `user`); `continue` запускает её снова.
- `DELETE .../{id}?confirm={id}` удаляет сессию вместе с её папкой. Папка, в которой сессия работала на месте,
  остаётся со всеми файлами и называется в ответе: `"folder_kept": {"root", "path"}`.

## Результат

`GET .../result` и последнее событие потока:

```json
{"type": "result", "status": "done", "session": "5f0c...", "goal": {...}, "summary": "...",
 "tasks": [{"id", "title", "status", "assignee", "parent_id", "crew"}], "cost_usd": 0.42, "duration_s": 180.5,
 "agents": ["Анна Смирнова"], "jobs": [], "error": null, "final": true, "board_url": null,
 "changed_files": [{"path": "summary.md", "change": "added"}], "changed_files_error": null,
 "changed_files_truncated": false}
```

- `status` — состояние сессии, `summary` — итог цели, когда она достигнута, `duration_s` — время от первого запуска до
  того, как сессия последний раз стала final, или до сейчас (null, если она ни разу не запускалась), `jobs` — фоновые
  процессы, которые ещё работают.
- `changed_files` перечисляет, что изменилось в папке сессии с её базового коммита (папка такой, какой она была при
  первом запуске, вместе со скопированными файлами): `added`, `modified` или `deleted`. Неотслеживаемые файлы
  считаются; файлы, которые игнорирует `.gitignore` папки, и `.scratch` — нет. Не больше 10 000 записей, первые по
  пути; тогда `changed_files_truncated` — true.
- `changed_files` равно null, а `changed_files_error` говорит почему, когда git для сессии выключен, git не
  установлен, у сессии нет базового коммита, этого коммита больше нет, у папки нет своего репозитория, настройки
  нельзя прочитать, git не справляется или папка, в которой сессия работает на месте, больше не проходит свои
  проверки.
- Итоговый (final) результат сохраняется и отдаётся снова как был, если только его `changed_files_error` не может
  пройти (git не установлен, что-то нельзя прочитать, git не справляется, папка на месте отклонена): тогда он
  вычисляется заново при следующем запросе.

## Файлы

- `GET .../files?path=` перечисляет одну папку файлов сессии (без `path` — саму папку сессии):
  `{"path", "entries": [{name, path, type: "file" | "dir", size, modified}]}`, по именам. Список всегда полный:
  постраничной выдачи нет.
- `GET .../files/{path}` скачивает один файл: `Content-Type: application/octet-stream` при любом имени (его написали
  агенты: сайт, который передаёт его дальше, не должен давать браузеру его отображать), `Content-Disposition:
  attachment` с именем, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store` и `Content-Length` — размер на
  момент открытия. Отправляется ровно столько байт: файл, который тем временем вырос, обрезается на этом месте; файл,
  который уменьшился, или чтение, которое не удалось, заканчивают ответ раньше, так что клиент, который сравнивает
  полученное с `Content-Length`, никогда не примет обрезанный файл за целый.
- `GET .../archive?path=` передаёт потоком zip папки сессии или одной папки внутри неё с именем `<папка>.zip`: каждая
  папка — отдельная запись (и пустые тоже), файлы сжаты и со своим временем, права 0644 (0755 для папок и исполняемых
  файлов). Сначала архив измеряется: больше `[api] archive_max_mb` (по умолчанию 1024) — 413 `too_large` до первого
  байта, а папка, которую нельзя прочитать, — 409 `conflict`, как и папка глубже 64 уровней. Каждый файл берётся в том
  размере, который был при его открытии. Файл или папка, которые пропадают, заменяются или уменьшаются, пока пишется
  zip, обрывают ответ до конца zip, так что клиент получает негодный zip, а не годный, в котором не хватает файлов. Хаб
  передаёт не больше 4 архивов сразу (от измерения до конца ответа, как бы медленно клиент ни читал): ещё один —
  429 `too_many_archives`; спросите позже или скачайте файлы по одному.
- Пути — относительно папки сессии, с `/`. Абсолютный путь, `..`, `.`, пустое имя, NUL, обратная косая черта,
  компонент `.git` или короткое имя Windows (`GIT~1`) — 400 `bad_name`; на хабе под Windows ещё `:`, `< > " | ? *`,
  зарезервированные имена (`CON`) и точка или пробел в конце.
- Никогда не перечисляются, не отдаются и не архивируются: ссылки; файлы с несколькими жёсткими ссылками (поэтому
  окружение, установленное жёсткими ссылками, как `.venv` от uv или `node_modules` от pnpm, пропускается); `.git` на
  любой глубине; `.scratch` (собственные файлы участников) без `scratch=true`; `.scratch/_skills` — никогда.
- Ничего не разыменовывается: ссылка или папка, которую заменили ссылкой во время чтения, заканчивает запрос, а не
  читает что-то за пределами папки сессии.
- Коды: 404 — путь не существует, это ссылка, файл с жёсткими ссылками или особый файл; 400 `bad_request` — папку
  запросили как файл или наоборот; 409 `conflict` — имя заменили во время открытия, или хаб не может прочитать файл;
  409 `folder_not_ready` — папки сессии нет или её нельзя прочитать; 403 `forbidden_folder` — к ней ведёт ссылка, или
  корень папки, в которой сессия работает на месте, это больше не разрешает.

## Папки на компьютере хаба

Клиент, чьи файлы уже лежат на компьютере хаба, называет там папку, а не загружает её. Назвать можно только папки под
корнем, который владелец указал в `[api] folders`, по имени корня и пути внутри него
([Настройки HTTP API](configuration.md#настройки-http-api)):

```json
"folder": {"root": "jobs", "path": "acme/site", "mode": "copy"}
```

- `path` — относительно корня, с `/`; пустой или отсутствующий — сам корень. Он подчиняется правилам имени, которое
  создаёт клиент (400 `bad_name`). Неизвестный корень — 400 `unknown_folder`; корень, которого нет, — 404; ссылка под
  корнем, которая ведёт наружу, или недопустимый корень (корень диска, ваша домашняя папка, домашняя папка DreamTeam
  или её собственные папки, другая домашняя папка DreamTeam, `/proc`, `/sys`, `/dev`, `/run`) — 403 `forbidden_folder`.
- **`copy`** (по умолчанию): папка или `.zip` под корнем копируется в собственную папку сессии, как
  [копия файлов](projects.md#работа-с-копией-файлов): `.git`, `node_modules`, `.venv`, `venv`, `__pycache__`, ссылки,
  особые файлы и файлы с несколькими жёсткими ссылками пропускаются, как и собственные имена сессии на верхнем
  уровне. Оригинал никогда не меняется, и несколько сессий могут копировать одну папку одновременно. Вместе с этим
  можно передать `files`; имя верхнего уровня, которое есть в обоих, — 409 `file_conflict`.
- **`in_place`** (только под корнем с `in_place = true`, иначе 403): сессия работает прямо в этой папке, как с
  [вашим проектом](projects.md): отсутствующая или пустая папка создаётся, папка с файлами подключается как есть, и
  агенты коммитят в её текущую ветку. С включённым git папка должна быть верхней папкой репозитория, на ветке, без
  незакоммиченного, с папкой `.git` внутри неё (не связанное рабочее дерево и не ссылка), — либо не входить ни в какой
  репозиторий (тогда она получает `git init` и первый коммит); иначе 409 `folder_not_ready`. Каждый запуск сессии
  заново проверяет корень и папку. `files` вместе с этим нельзя (400): положите файлы в папку сами.
- **Одна папка — одна сессия.** Папка, в которой работает другая сессия, или папка внутри неё или вокруг неё — 409
  `folder_busy`; его `session` называет id той сессии, если токен её видит. Следующее указание туда отправляйте через
  `continue`; DELETE освобождает папку и оставляет её файлы.
- Сводки называют папку как `{"root", "path", "mode"}`, а тексты ошибок — как `<root>/<path>`: никогда не путём на
  компьютере хаба.

## Ошибки

| код | статус | когда |
|---|---|---|
| `token_required` | 401 | нет верного `Authorization: Bearer` (с `WWW-Authenticate: Bearer realm="DreamTeam"`) |
| `api_disabled` | 403 | у хаба нет ни токена API, ни токена хаба |
| `forbidden_host`, `forbidden_origin` | 403 | `Host`, который хаб не принимает, или страница с другого origin |
| `unsupported_media_type` | 415 | POST или PATCH не с `application/json`, загрузка другого типа |
| `bad_request` | 400 | тело или значение, которое API не может принять |
| `unknown_field` | 400 | поле, которого API не знает |
| `unknown_team`, `unknown_model`, `unknown_role`, `unknown_skill`, `unknown_folder` | 400 | имя, которого у хаба нет; в тексте — список имён |
| `bad_name` | 400 | имя файла или путь, которые хаб отклоняет |
| `forbidden_folder` | 403 | папка вне того, что разрешает `[api] folders` |
| `not_found` | 404 | нет такой сессии, файла, запроса, загрузки, корня или маршрута (для токена API — и сессия, созданная не через API) |
| `method_not_allowed` | 405 | метод, которого маршрут не принимает (`Allow` перечисляет те, что принимает) |
| `conflict` | 409 | состояние сейчас этого не позволяет, или рой отказался |
| `earlier_version` | 409 | сессия, созданная более ранней версией DreamTeam |
| `file_conflict` | 409 | два файла с одним именем в одном создании |
| `folder_busy` | 409 | в этой папке работает другая сессия |
| `folder_not_ready` | 409 | папки нет, или репозиторий не готов к работе |
| `not_running` | 409 | ответ или сообщение остановленной сессии |
| `budget_exhausted` | 409 | бюджет исчерпан: поднимите его через PATCH |
| `too_large` | 413 | тело, загрузка, копия или архив больше своего лимита |
| `too_many_uploads` | 429 | уже ждут `[api] uploads_pending` загрузок |
| `too_many_sessions` | 429 | уже работают `[api] max_running` сессий |
| `too_many_archives` | 429 | хаб уже передаёт 4 архива |
| `internal` | 500 | хаб не справился или останавливается; почему — в его логе. Спросите позже |

Для токена API текст ошибки никогда не называет путь на компьютере хаба: папка сервера читается как `<root>/<path>`,
домашняя папка и папки сессии — по своим именам, любой другой путь — по последней части.

## Совместимость

В пределах v1 поля, коды, состояния и типы событий только добавляются, но никогда не переименовываются, не удаляются
и не получают другого смысла, поэтому клиент пропускает то, чего не знает. `text` событий и ошибок — для людей, и его
формулировка может меняться. Всё остальное становится `/api/v2`, и тогда v1 остаётся ещё хотя бы на один минорный
выпуск. `GET /api/v1/options` называет версию DreamTeam.

## Безопасность

- **Куда достаёт токен API.** Только до `/api/v1`: ни одного маршрута доски, ни `/mcp`, ни WebSocket. С ним клиент не
  может ни изменить настройки, ни прочитать ключи профилей моделей, ни добраться до сессии, созданной не через API,
  ни назвать папку вне `[api] folders`. Это ограничивает то, что клиент может назвать, а не то, до чего могут добраться
  агенты: токен API — это право запустить цель. Агенты выполняют команды с правами пользователя хаба (в песочнице — с
  правами контейнера), поэтому могут прочитать домашнюю папку, её настройки (в `dreamteam.toml` может быть ключ) и
  ключи в ней, а загруженный документ может содержать указания для них. Каждый корень `[api] folders` — ещё одно
  разрешение тому, у кого токен: с `in_place` агенты пишут туда.
- **Кто что видит.** Токен API видит только сессии, созданные через API (любая другая сессия для него — 404), кто бы
  их ни создал: сессию, которую вы создали на `/api/v1` с токеном хаба, с токеном API тоже можно прочитать,
  продолжить, остановить и удалить. Свою работу, которую сайту трогать нельзя, запускайте на доске, в терминале или
  через `/mcp`. Токен хаба видит все сессии. Сессия `main` старого проекта недоступна никогда.
- **Хаб для сайта** запускайте в [`dreamteam sandbox`](sandbox.md#http-api-в-песочнице): агенты выполняют команды, и
  загруженный документ может содержать указания для них, а хаб на одном компьютере с сайтом без токена хаба открывает
  остальные свои маршруты ошибкам сайта (подделка запроса доходит до `127.0.0.1`). Вне песочницы дайте хабу и токен
  хаба.
- **Другой компьютер.** Хабу, который слушает адрес не loopback, токен хаба нужен в любом случае
  ([Безопасность](security.md)); имя, которым пользуется клиент, добавьте в `DREAMTEAM_ALLOWED_HOSTS`. Хаб говорит по
  обычному HTTP, поэтому по сети токен и загруженные файлы идут незашифрованными: поставьте перед хабом обратный
  прокси, который снимает TLS, и задайте `DREAMTEAM_PUBLIC_URL` ([Безопасность](security.md)).
- **Без CORS.** Страница с другого origin отклоняется, как и на доске: сайт обращается к API со своего сервера, а не из
  браузеров посетителей, и никогда не показывает им токен.
- **Файлы — агентов.** Скачивание отдаётся как `application/octet-stream` с `nosniff`, поэтому браузер их не
  отображает, а тексты событий, результаты задач, сообщения и файлы содержат то, что написали агенты, включая пути на
  компьютере хаба: API их не вычищает.
