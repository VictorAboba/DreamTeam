# Features

**English** · [Русский](../ru/features.md) · [All docs](README.md)

| | |
|---|---|
| **Task board** | The swarm's global goal and the tasks the swarm sets for itself. Every task has a **goal** (why it is needed and what counts as success), an assignee, a reviewer, a status (`todo → in_progress → waiting → review → done / failed / cancelled`), a priority, tags, subtasks and dependencies. Claiming a task is atomic; a task with unfinished dependencies cannot be claimed. An agent's task is accepted by another agent (independent review); if nobody else is left, by you. |
| **Task discussion** | Every task has its own discussion thread: posts, replies (`reply_to`) and mentions `@First Last`. The task author, the assignee, the reviewer, everyone who posted in the thread and everyone mentioned get notifications. |
| **Self-organization** | There is no leader. When a goal is set, a planning task appears on the board. The first free agent takes it, and the others join in on ready tasks. If the agent that took it has not created a single task after 8 steps or 10 minutes, it is hinted to create independent tasks right away and hand research to others (`[agents] planning_hint_steps`, `planning_hint_minutes`). If there are free tasks, the scheduler wakes idle agents. |
| **Names and hiring** | Every agent gets a unique human name: "Anna Smirnova" or "John Smith". Agents hire new role agents (`hire_agent`) within a limit. Roles come from the [role catalog](configuration.md#roles-and-the-starting-team); you can add your own. |
| **Messages** | Direct messages to one, several or all members, and to the user. If you wrote to an agent, its text reply comes to you. |
| **Shared workspace** | Shared files under git: every change is committed automatically in the agent's name; agents do not commit by hand. A new file that appears after a command enters the history when it survives the next command, or when a task is handed in, at the end of the agent's turn, or on stop: this way leftovers of a test run, which the next run deletes, do not clutter the history. Agents put temporary files in `.scratch/` (each has its own folder): it is not committed, and DreamTeam does not clean it. Files can be locked while they are being edited. |
| **Console** | Agents run commands (bash or PowerShell) in the workspace. API keys from the environment are hidden. A command that does not finish within its timeout is not killed; it keeps running as a **background job**: the agent gets its output at once and does other work, and learns about the end of the job with the exit code and the tail of the output. An agent can also start a dev server, a build or long tests in the background itself. Background jobs are shown on the "Jobs" tab of the web board and by the `/jobs` command in the terminal, and can be stopped there. Pausing the swarm does not stop them; stopping the session does. |
| **Triggers** | A safe mini-language for conditions of any complexity: `done(1, 5)`, `status(3) in (failed, cancelled) or count(status=done, tag="api") >= 3`, `message(sender="Anna Smirnova")`, `comment(task=7)`, `file_changed("report.md")`, `after("2026-10-09 18:00")`, `every(1800)`. When a trigger fires, an agent wakes up, a message is sent, a status changes or a task is created. |
| **MCP workshop** | An agent writes an MCP server in Python (`mcp_create`). The server passes an automatic check and is registered with a scope: personal, for a task or for the whole swarm. All permitted agents use it (`mcp_tools`, `mcp_call`). Swarm servers go to the shared library and are available in later runs. Optionally, new MCP servers require the user's approval. |
| **Skills** | [Skills](skills.md) in the Agent Skills format (a folder with `SKILL.md`) are attached to a session at start or on the fly: from the shared library, from Claude Code (`~/.claude/skills`), from a folder, a zip archive or a Git repository. All swarm members see them, roles from the catalog get their own skills automatically, and members propose new ones, which you save to the library. The dependencies of a skill's scripts (`requirements.txt`, `pyproject.toml`, `package.json`) are installed automatically into a separate environment. |
| **The swarm as MCP** | `/mcp` over HTTP or `dreamteam mcp` over stdio. An external client acts as the user or joins the swarm (`join_swarm`) and works as a member. |
| **Sessions** | A start page with the list of sessions: each shows its status, goal, task progress, team, costs, model and time of last activity. A session can be opened, stopped, started again or deleted. A stopped session can be opened too: the board, messages, files and traces are available for viewing. Each session is an independent swarm with its own board, messages, workspace, MCP and traces. Sessions that were running when the server stopped resume on the next start. A session can be [moved to another folder or pointed at an existing project](projects.md) with the `/cd` command. |
| **Settings in the UI** | Model profiles: Anthropic, OpenAI, OpenRouter, Ollama, vLLM, LM Studio or your own OpenAI-compatible endpoint. The key is set as an environment variable or as the value itself; it is not sent to the browser (nor are the `env` values of external MCP servers: they are shown masked). There are "Check" (the endpoint's model list) and "Test request" buttons. You can also set defaults for new sessions, agents, console, workspace, MCP, traces and server. Changes to models and limits apply to running sessions at once; server settings apply after a restart. |
| **Agent traces** | Every agent wake-up is saved as a trace of steps: what woke it; every LLM call with the model, thinking, reply, tool calls, tokens (including cache), cost, latency and stop reason; retries; every tool with full arguments and result; context compaction; the outcome. For any LLM call you can open the exact request context, even after the history was compacted. The "Traces" tab shows a waterfall of steps and statistics per tool and model. Traces can be exported to JSON/JSONL, read with `dreamteam traces` and through the MCP tool `agent_traces`. Traces are also written for external members (Claude Code over MCP). |
| **Claude Code-style terminal** | `dreamteam` in a terminal opens an interactive interface. It has a welcome screen, a framed input box and a status line. Slash commands and `@agents` are suggested as you type. The swarm's action feed looks like this: `⏺ Agent · tool(...)` and below it `⎿ result`. Tasks are marked `☐ ◐ ☒`. While agents work, a spinner shows the time, tokens and cost, and `esc` pauses the swarm. MCP servers are approved through a dialog. `!command` runs a command in the workspace. `dreamteam -p "goal"` works without the interface for scripts and CI and prints `text`, `json` or `stream-json`. |
| **Live board** | A web interface with live updates: a kanban board with drag and drop, task cards with discussion, a chat with any agent and its action feed (thinking, tool calls, results), and tabs with the swarm event feed, files, MCP, triggers and agents' background jobs (their output and a "Stop" button). Messages, task descriptions and results, discussions, the goal and `.md` files are shown as formatted Markdown (a safe subset: HTML in the text is shown as text); code in files and in code blocks is highlighted (about 30 languages, no external libraries). There is RU/EN and a light/dark theme. |
| **Models** | Claude API, OpenAI, OpenRouter, vLLM, Ollama and any OpenAI-compatible proxy. Model profiles are set in the config; different agents can be given different models. |
| **Budget** | Token and money accounting per agent. When the budget runs out, the swarm pauses. There is a limit on the number of agents. |
| **Languages** | Agent prompts in Russian or English (`swarm.language`; the language can also be set for a single agent). |
| **Sandbox** | `dreamteam sandbox` runs the whole swarm in Docker together with the agents' console and their MCP servers. |
| **Reliability** | Everything is stored in one SQLite file. After a restart the swarm continues from the same place: agent history is restored, and interrupted tool calls are closed properly. |
